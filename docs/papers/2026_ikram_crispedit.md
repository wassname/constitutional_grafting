# CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing

Zarif Ikram    Arad Firouzkouhi    Stephen Tu    Mahdi Soltanolkotabi    Paria Rashidinejad Affiliation: University of Southern California Email: <%7Bzikram,firouzko,stephen.tu,soltanol,paria.rashidinejad%7D@usc.edu>

February 17, 2026

###### Abstract

A central challenge in large language model (LLM) editing is capability preservation: methods that successfully change targeted behavior can quietly game the editing proxy and corrupt general capabilities, producing degenerate behaviors reminiscent of proxy/reward hacking. We present CrispEdit, a scalable and principled second-order editing algorithm that treats capability preservation as an explicit constraint, unifying and generalizing several existing editing approaches. CrispEdit formulates editing as constrained optimization and enforces the constraint by projecting edit updates onto the low-curvature subspace of the capability-loss landscape. At the crux of CrispEdit is expressing capability constraint via *Bregman divergence*, whose quadratic form yields the Gauss–Newton Hessian exactly and even when the base model is not trained to convergence. We make this second-order procedure efficient at the LLM scale using Kronecker-factored approximate curvature (K-FAC) and a novel *matrix-free projector* that exploits Kronecker structure to avoid constructing massive projection matrices. Across standard model-editing benchmarks, CrispEdit achieves high edit success while keeping capability degradation below 1% on average across datasets, significantly improving over prior editors.

## 1 Introduction

Figure 1: Comparison overview of CrispEdit. CrispEdit achieves strong edit reliability and generality, with and without QA context, while preserving broad base capabilities (MMLU, GSM8K, IFEval, ARC-C, TruthfulQA) on LLaMA-3-8B-Instruct.

Large language models (LLMs) are rapidly becoming a shared backbone for knowledge work, spanning search and question answering ([Gao et al., 2023b](#bib.bib53); [Lewis et al., 2020](#bib.bib54)), science ([Jumper et al., 2021](#bib.bib55)), software development ([Chen, 2021](#bib.bib56)), decision support ([Lopez-Lira and Tang, 2023](#bib.bib57)), and education ([Kasneci et al., 2023](#bib.bib58)). Yet every day, facts shift, new discoveries land, products ship, hallucinations or unsafe behaviors are uncovered, quickly making the models stale. Retraining from scratch is the cleanest way to absorb this drift, but it is also the most expensive and slowest. Model editing ([Sinitsin et al., 2020](#bib.bib30); [De Cao et al., 2021](#bib.bib31); [Mitchell et al., 2022b](#bib.bib4); [Wang et al., 2024c](#bib.bib26)) offers a practical alternative: apply targeted updates to correct a fact, insert new knowledge, remove unsafe behavior, personalize the style *while leaving everything else intact*.

![Refer to caption](2602.15823v2/header.png)

This allows changes in representations to satisfy the edit while moving along the “valley” of the landscape to maintain general model capabilities.

In many cases, edits may appear to succeed while quietly degrading broader capabilities reminiscent of reward/proxy hacking [Gao et al. (2023a)](#bib.bib61). This degradation can manifest as brittle reasoning, weaker instruction-following, or even broken fluency. In response, prior work has introduced heuristic guardrails: restrict updates to a small set of parameters ([Hu et al., 2022](#bib.bib44); [Yu et al., 2024](#bib.bib6)), localize “where the knowledge lives,” ([Meng et al., 2022](#bib.bib9); [Yang et al., 2025b](#bib.bib24); [Gu et al., 2025](#bib.bib15)) or constrain representation changes (e.g., via subject-centric “knowledge vectors”) ([Meng et al., 2023](#bib.bib11); [Fang et al., 2025](#bib.bib13)). Despite improvements, these methods tend to bake in strong assumptions about edit structure (e.g., explicit subjects/entities) and impose constraints in parameter or representation space that are only indirectly tied to capability preservation, resulting in a poor edit–preservation trade-off. Indeed, editors built on such constraints still perform poorly when tested *in the wild* under natural autoregressive generation, despite looking strong under unrealistic teacher-forced evaluation that scaffolds the ground-truth prefix and target length ([Yang et al., 2025a](#bib.bib37)).

In this paper, we adopt a first-principles formulation of model editing: an edit should reduce an edit loss while leaving broader capabilities effectively unchanged. Accordingly, we pose editing as a constrained optimization problem that seeks to minimize the edit loss subject to negligible changes in capability loss, measured on a designated capability set via a distance metric ([Section 2](#S2 "2 The Model editing problem ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing")). Standard approaches that replace the constraint with a soft penalty typically require nontrivial tuning and can be prohibitively expensive when the capability set is far larger than the edit set. This motivates us to ask: *How to enforce capability preservation directly, without turning editing into full retraining?*

To address this, we introduce CrispEdit (Curvature-Restricted In-Situ Parameter Editing), a scalable non-destructive editor, built around the following core ideas.

1. Preserving capabilities with low-curvature projections. A core idea behind CrispEdit is that not all parameter directions are equally important for preserving a model’s capabilities. Recent work shows that the curvature of the pretrained loss landscape can be characterized by the Hessian, which is observed to be highly anisotropic: sharp in a small number of directions and flat in others ([Sagun et al., 2017](#bib.bib36); [Oymak et al., 2019](#bib.bib34); [Ghorbani et al., 2019](#bib.bib35); [Kalra et al., 2026](#bib.bib62)). CrispEdit exploits this structure by projecting updates into low-curvature subspaces of Hessian, effectively “hiding” parameter movement where capabilities are minimally affected (see [Figure 2](#S1.F2 "In 1 Introduction ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing") and [Section 3.1](#S3.SS1 "3.1 Preserving capabilities with low-curvature updates ‣ 3 CrispEdit: Curvature-Restricted In-Situ Parameter Editing ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing")).

2. Avoiding base model convergence requirement with Bregman constraint. A quadratic approximation based on the standard Hessian—which instantiates our formulation with a Euclidean distance—requires assuming that the base model is trained to (near)-convergence, which is rarely satisfied in practice for modern large networks. We resolve this by measuring capability preservation using *Bregman divergence*. This choice yields a quadratic form expressed exactly in terms of the *Gauss-Newton Hessian* (GNH), even when the base model is not trained to convergence, avoiding stationarity assumptions.

3. Representation constraints as a restrictive special case. Our Bregman-GNH formulation also sheds light on several successful prior heuristics. We prove (see [Proposition 1](#Thmproposition1 "Proposition 1 (AlphaEdit is more conservative). ‣ 3.2 Gauss-Newton constraint via Bregman divergence ‣ 3 CrispEdit: Curvature-Restricted In-Situ Parameter Editing ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing")) popular editors such as AlphaEdit ([Fang et al., 2025](#bib.bib13)) and Adam-NSCL ([Wang et al., 2021](#bib.bib22)) solve an approximate special case of our framework, but do so within *far more restrictive* and lower-dimensional subspaces, leading to a worse capability preservation-edit tradeoff ([Figure 1](#S1.F1 "In 1 Introduction ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing")).

4. Scalable matrix-free low-curvature projectors. The remaining challenge is scale: how can we efficiently compute and store curvature information for billion-parameter transformers? CrispEdit addresses this with two key ideas:

1.  (a)
    The resulting GNH is amenable to accurate approximations via Kronecker-factored approximate curvature ([Martens and Grosse, 2015](#bib.bib2), K-FAC), which we leverage to enable efficient computation of the low-curvature projection matrix.
2.  (b)
    Instead of explicitly constructing a low-curvature projection matrix, we introduce ([Section 3.3](#S3.SS3 "3.3 K-FAC for scalable, matrix-free projections ‣ 3 CrispEdit: Curvature-Restricted In-Situ Parameter Editing ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing")) a matrix-free projector that exploits the Kronecker eigen-structure: rotate gradients into a factored eigenbasis, mask high-curvature components, and rotate back. This makes constraint-aware second-order editing feasible and enables precomputing capability curvature statistics once and reusing them across many future edits, amortizing cost and enabling batch and sequential editing.

Experimental results. We evaluate CrispEdit in both small- and large-scale regimes. In controlled small-scale experiments on image classification (MNIST $\mapsto$ FashionMNIST), where calculating exact curvature is feasible, we show that Hessian low-curvature projections yield the strongest capability preservation, and that K-FAC closely tracks this behavior cheaply. We then scale CrispEdit to edit LLMs (e.g., LLaMA-3-8B-Instruct and Qwen-2.5-1.5B-Instruct) and evaluate them as used in practice: edits should be *reliable* in standalone autoregressive generations, *generalize* across semantically equivalent in-scope queries, and remain *local*, preserving out-of-scope knowledge and broad skills such as reasoning, instruction-following, and truthfulness. We further test our method in both batch editing, where many edits are applied at once, and sequential editing, where batches of edits are applied to the model sequentially. Across settings, CrispEdit consistently improves the edit–capability trade-off, achieving strong edit success while substantially reducing capability degradation, with modest compute and storage requirements.¹¹ 1 Using cached curvature, 3000 edits with our method takes six minutes on an NVIDIA A40 GPU.

## 2 The Model editing problem

Let $f_{\mathbf{θ}}:{\mathcal{X}\mapsto\mathcal{Y}}$ denote a model with parameters ${\mathbf{θ}} \in \Theta \subseteq {\mathbb{R}}^{p}$, mapping inputs $x \in \mathcal{X}$ to outputs $y \in \mathcal{Y}$. Model editing seeks to update a pretrained (base) model $f_{{\mathbf{θ}}_{0}}$ with initial parameters ${\mathbf{θ}}_{0}$, using a provided edit target pair ${(x,y)} \in {\mathcal{X} \times \mathcal{Y}}$, while preserving the existing capabilities of the base model. We formalize this as follows.

Let $\mathcal{D}_{\text{cap}} = {\{{(x_{i},y_{i})}\}}_{i = 1}^{n}$ be a reference dataset that serves as a proxy for capabilities we wish to preserve, an exemplar of the domains on which the model should continue to perform well. We formulate capability preservation through the empirical loss

|     |                                                                                                                                                                                                            |     |
|-----|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----|
|     | $${{\mathcal{L}_{\text{cap}}\hspace{0pt}{({\mathbf{θ}},\mathcal{D}_{\text{cap}})}}:={\frac{1}{n}\hspace{0pt}{\sum\limits_{i = 1}^{n}{\ell\left( {f_{\mathbf{θ}}\hspace{0pt}{(x_{i})}},y_{i} \right)}}}},$$ |     |

where $\ell{(\hat{y},y)}$ is a task-appropriate loss (e.g., cross entropy). Preserving capabilities then means keeping $\mathcal{L}{({\mathbf{θ}},\mathcal{D}_{\text{cap}})}$ close to its pre-edit value, i.e., ${\mathcal{L}{({\mathbf{θ}},\mathcal{D}_{\text{cap}})}} \approx {\mathcal{L}{({\mathbf{θ}}_{0},\mathcal{D}_{\text{cap}})}}$. Let $\mathcal{D}_{\text{edit}} = {\{{(x_{i},y_{i})}\}}_{i = 1}^{T}$ be the edit dataset containing the desired edit pairs. We write $\mathcal{L}_{\text{edit}}\hspace{0pt}{({\mathbf{θ}},\mathcal{D}_{\text{edit}})}$ to denote an edit loss, such as the negative log-likelihood of edit outputs. Using the language of constrained optimization, a natural optimization problem that expresses our desire to minimize edit loss subject to preserving capabilities is the following:²² 2 We will drop the dependency of the capabilities and edit losses on datasets $\mathcal{D}_{\text{edit}}$ and $\mathcal{D}_{\text{cap}}$ when it is clear from the context.

|     |                                                                                                                                                                                                                                                                                         |     |     |
|-----|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----|-----|
|     | ${{{\min\limits_{{\mathbf{θ}} \in \Theta}\mathcal{L}_{\text{edit}}}\hspace{0pt}{({\mathbf{θ}})}}\quad\text{s.t.}\quad{{\mathsf{d}\left( {\mathcal{L}_{\text{cap}}\hspace{0pt}{({\mathbf{θ}})}},{\mathcal{L}_{\text{cap}}\hspace{0pt}{({\mathbf{θ}}_{0})}} \right)} \leq \varepsilon}},$ |     | (1) |

where $\mathsf{d}{( \cdot , \cdot )}$ is a measure of distance, such as the difference between the two loss values or the Bregman divergence, and $\varepsilon$ is a small tolerance value. The above formulation is general, unifying and extending many existing model editing frameworks as we discuss in [Section 5](#S5 "5 Related work ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing").

While Problem ([1](#S2.E1 "Equation 1 ‣ 2 The Model editing problem ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing")) rigorously expresses our desired intent for model editing, actually solving ([1](#S2.E1 "Equation 1 ‣ 2 The Model editing problem ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing")), especially at LLM scale, is challenging due to the hard constraint. We note that we focus on the constrained formulation above in lieu of the standard Lagrangian relaxation to ([1](#S2.E1 "Equation 1 ‣ 2 The Model editing problem ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing")), namely ${{\min_{{\mathbf{θ}} \in \Theta}\mathcal{L}_{\text{edit}}}\hspace{0pt}{({\mathbf{θ}})}} + {\lambda\hspace{0pt}\mathsf{d}\hspace{0pt}\left( {\mathcal{L}_{\text{cap}}\hspace{0pt}{({\mathbf{θ}})}},{\mathcal{L}_{\text{cap}}\hspace{0pt}{({\mathbf{θ}}_{0})}} \right)}$. This is due to the fact that in typical operating regimes $n$ (the number of reference pairs) far exceeds $T$ (the number of edits), and the computational overhead of gradient-based optimization on the unconstrained problem can be non-trivial. We avoid this complexity by considering an alternative approach to approximating ([1](#S2.E1 "Equation 1 ‣ 2 The Model editing problem ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing")) based on low-curvature projections.

## 3 CrispEdit: Curvature-Restricted In-Situ Parameter Editing

We now present CrispEdit for solving Problem ([1](#S2.E1 "Equation 1 ‣ 2 The Model editing problem ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing")). The key idea is to edit only along directions that are locally “safe” for maintaining capabilities as informed by the constraint. We start in [Section 3.1](#S3.SS1 "3.1 Preserving capabilities with low-curvature updates ‣ 3 CrispEdit: Curvature-Restricted In-Situ Parameter Editing ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing") with a simple instantiation of CrispEdit under the standard capability loss difference and derive a principled curvature-restricted model-editing algorithm. Then, in [Section 3.2](#S3.SS2 "3.2 Gauss-Newton constraint via Bregman divergence ‣ 3 CrispEdit: Curvature-Restricted In-Situ Parameter Editing ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing"), we leverage *Bregman divergences* to derive a practical editing approach that scales to billion-parameter LLMs.

For what follows, we assume that both the maps $\hat{y}\mapsto{\ell{(\hat{y},y)}}$ and ${\mathbf{θ}}\mapsto{f_{\mathbf{θ}}\hspace{0pt}{(x)}}$ are twice continuously differentiable over their respective domains. This immediately holds for architectures with smooth activation functions such as GeLU/SwiGLU. Furthermore, this assumption can readily be relaxed to functions that are twice differentiable except on a measure zero set, such as architectures with ReLU activations; for simplicity of exposition, we omit these details.

### 3.1 Preserving capabilities with low-curvature updates

We first consider the distance measure to be the standard distance ${\mathsf{d}{(a,b)}} = {|{a - b}|}$. Furthermore, in this section, we assume that the base parameters ${\mathbf{θ}}_{0}$ are a local minima of the capabilities loss $\mathcal{L}_{\text{cap}}\hspace{0pt}{({\mathbf{θ}})}$; we remove this assumption in [Section 3.2](#S3.SS2 "3.2 Gauss-Newton constraint via Bregman divergence ‣ 3 CrispEdit: Curvature-Restricted In-Situ Parameter Editing ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing") by using a different distance measure. Applying a second-order Taylor expansion to the constraint in ([1](#S2.E1 "Equation 1 ‣ 2 The Model editing problem ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing")) yields ${{\mathcal{L}_{\text{cap}}\hspace{0pt}{({\mathbf{θ}})}} - {\mathcal{L}_{\text{cap}}\hspace{0pt}{({\mathbf{θ}}_{0})}}} \approx {\frac{1}{2}\hspace{0pt}{({{\mathbf{θ}} - {\mathbf{θ}}_{0}})}^{\top}\hspace{0pt}{\mathbf{H}}_{\text{cap}}\hspace{0pt}{({{\mathbf{θ}} - {\mathbf{θ}}_{0}})}}$, where ${\mathbf{H}}_{\text{cap}} ≔ {\nabla_{\theta}^{2}\hspace{0pt}\mathcal{L}_{\text{cap}}\hspace{0pt}{({\mathbf{θ}}_{0})}}$ is the Hessian of the capability loss function evaluated at ${\mathbf{θ}}_{0}$, and the first term in Taylor expansion is zero because ${{\nabla_{\theta}\mathcal{L}_{\text{cap}}}\hspace{0pt}{({\mathbf{θ}}_{0})}} = 0$. Under this setting, ([1](#S2.E1 "Equation 1 ‣ 2 The Model editing problem ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing")) can be approximated by optimizing the following quadratically constrained optimization problem:

|     |                                                                                                                                                                                                                                                                                 |     |     |
|-----|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----|-----|
|     | ${{{\min\limits_{{\mathbf{θ}} \in \Theta}\mathcal{L}_{\text{edit}}}\hspace{0pt}{({\mathbf{θ}})}}\quad\text{s.t.}\quad{{{({{\mathbf{θ}} - {\mathbf{θ}}_{0}})}^{\top}\hspace{0pt}{\mathbf{H}}_{\text{cap}}\hspace{0pt}{({{\mathbf{θ}} - {\mathbf{θ}}_{0}})}} \leq \varepsilon}}.$ |     | (2) |

In the deep learning literature, it is well-understood that in typical overparameterized settings, the Hessian ${\mathbf{H}}_{\text{cap}}$ at the end of training is usually low-rank [Sagun et al. (2017)](#bib.bib36); [Oymak et al. (2019)](#bib.bib34); [Ghorbani et al. (2019)](#bib.bib35). Thus, the ellipsoidal constraint in ([2](#S3.E2 "Equation 2 ‣ 3.1 Preserving capabilities with low-curvature updates ‣ 3 CrispEdit: Curvature-Restricted In-Situ Parameter Editing ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing")) offers many parameter directions around ${\mathbf{θ}}_{0}$ of *low-curvature*, where the capability loss $\mathcal{L}_{\text{cap}}$ remains (approximately) invariant. These low-curvature directions enable the optimization ([2](#S3.E2 "Equation 2 ‣ 3.1 Preserving capabilities with low-curvature updates ‣ 3 CrispEdit: Curvature-Restricted In-Situ Parameter Editing ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing")) to decrease the edit loss $\mathcal{L}_{\text{edit}}$, while limiting loss of capabilities. Furthermore, compared to the Lagrange relaxation objective, the quadratic constraint offers several key advantages:

1.  (a)
    Strict control of capability loss: The ellipsoidal constraint can be enforced via projected gradient or trust-region methods, enabling strict control of tolerated capability degradation; we discuss this shortly.
2.  (b)
    Scalability to billion-parameter models: The second-order relaxation of the constraint forms the foundation for efficiently scaling our approach to billion-parameter LLMs leveraging Bregman divergences (cf. [Section 3.2](#S3.SS2 "3.2 Gauss-Newton constraint via Bregman divergence ‣ 3 CrispEdit: Curvature-Restricted In-Situ Parameter Editing ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing")).
3.  (c)
    Pre-computation: The curvature model ${\mathbf{H}}_{\text{cap}}$ can be precomputed once and reused across many subsequent edits, amortizing cost and enabling sequential and online interventions (cf. [Section 3.4](#S3.SS4 "3.4 Sequential editing via online projection updates ‣ 3 CrispEdit: Curvature-Restricted In-Situ Parameter Editing ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing")).

Projected low-curvature gradient descent. We can enforce the constraint in ([2](#S3.E2 "Equation 2 ‣ 3.1 Preserving capabilities with low-curvature updates ‣ 3 CrispEdit: Curvature-Restricted In-Situ Parameter Editing ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing")) by ensuring that the weight changes ${\Delta\hspace{0pt}{\mathbf{θ}}} = {{\mathbf{θ}} - {\mathbf{θ}}_{0}}$ are in the (approximate) null-space of the Hessian ${\mathbf{H}}_{\text{cap}}$, i.e., ${{\mathbf{H}}_{\text{cap}}\hspace{0pt}\Delta\hspace{0pt}{\mathbf{θ}}} \approx 0$ which is equivalent to ${\Delta\hspace{0pt}{\mathbf{θ}}} \in {{\mathsf{N}\mathsf{u}\mathsf{l}\mathsf{l}}{({\mathbf{H}}_{\text{cap}})}}$. A sufficient condition to enforce the constraint during gradient descent is projecting the gradients to the approximate null-space of ${\mathbf{H}}_{\text{cap}}$ at every gradient step.

Let ${\mathbf{H}}_{\text{cap}} = {{\mathbf{U}}\hspace{0pt}\mathbf{\Sigma}\hspace{0pt}{\mathbf{U}}^{\top}}$ be the eigen-decomposition of ${\mathbf{H}}_{\text{cap}}$, where $\mathbf{\Sigma} = {{\mathsf{d}\mathsf{i}\mathsf{a}\mathsf{g}}{(\sigma_{1},\ldots,\sigma_{p})}}$ and $\sigma_{1} \geq \cdots \geq \sigma_{p} \geq 0$ (recall that ${\mathbf{θ}}_{0}$ is locally optimal). We construct a low-curvature projector by discarding the top eigenspace. Concretely, given an energy threshold $\gamma \in {(0,1)}$, let $k:={\min{\{{r \in {\lbrack p\rbrack}}\mid{{{\sum_{i = 1}^{r}\sigma_{i}}/{\sum_{i = 1}^{p}\sigma_{i}}} \geq \gamma}\}}}$ denote the minimum index capturing $\gamma$-fraction of the eigenspectrum. Then, the orthogonal projection to the *remaining* directions ${\mathbf{U}}_{\phantom{} > k} ≔ {\lbrack{u_{k + 1}\hspace{0pt}{\mid \ldots \mid}\hspace{0pt}u_{p}}\rbrack}$ can be computed as:

|     |                                                                                                                                                                                                                                                                                     |     |     |
|-----|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----|-----|
|     | ${{{\mathbf{g}}_{t}^{\text{proj}} = {{\mathbf{P}}_{\gamma}\hspace{0pt}{\nabla_{\mathbf{θ}}\mathcal{L}_{\text{edit}}}\hspace{0pt}{({\mathbf{θ}}_{t})}}},\text{where}\quad{{\mathbf{P}}_{\gamma}:={{\mathbf{U}}_{\phantom{} > k}\hspace{0pt}{\mathbf{U}}_{\phantom{} > k}^{\top}}}}.$ |     | (3) |

Intuitively, the projection in ([3](#S3.E3 "Equation 3 ‣ 3.1 Preserving capabilities with low-curvature updates ‣ 3 CrispEdit: Curvature-Restricted In-Situ Parameter Editing ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing")) removes the components of the edit gradient that point in the directions where capability loss is sensitive. We will refer to the subspace spanned by ${\mathbf{U}}_{\phantom{} > k}$ as the $\gamma$-approximate nullspace.

### 3.2 Gauss-Newton constraint via Bregman divergence

In [Section 3.1](#S3.SS1 "3.1 Preserving capabilities with low-curvature updates ‣ 3 CrispEdit: Curvature-Restricted In-Situ Parameter Editing ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing") and deriving ([2](#S3.E2 "Equation 2 ‣ 3.1 Preserving capabilities with low-curvature updates ‣ 3 CrispEdit: Curvature-Restricted In-Situ Parameter Editing ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing")), we assumed that ${{\nabla_{\mathbf{θ}}\mathcal{L}_{\text{cap}}}\hspace{0pt}{({\mathbf{θ}}_{0})}} = 0$. However, in training neural networks, especially LLMs, one typically does not train the network to convergence, to avoid overfitting. Moreover, the capability loss can only be viewed as a mere proxy to the pretraining loss. To avoid relying on the linear term vanishing, we instantiate CrispEdit using a *Bregman divergence* that is always first-order flat at ${\mathbf{θ}}_{0}$.

A key property of Bregman divergence is that in the second-order Taylor approximation, the gradient is zero for any fixed $\mathbf{θ}$, resulting in the following (cf. where ${\mathbf{G}}_{\text{cap}}$ is the Gauss-Newton Hessian (GNH, also referred to as the Generalized Gauss-Newton), defined as ${\mathbf{G}}_{\text{cap}}:={{\mathbb{E}}_{\mathcal{D}_{\text{cap}}}\hspace{0pt}\left\lbrack {{\mathbf{J}}^{\top}\hspace{0pt}{\mathbf{H}}_{\hat{y}}\hspace{0pt}{\mathbf{J}}} \right\rbrack}$. Here, ${\mathbf{J}} = {{\nabla_{\mathbf{θ}}f_{\mathbf{θ}}}\hspace{0pt}{(x)}}$ is the network’s parameter-output Jacobian, and ${\mathbf{H}}_{\hat{y}} = {\nabla_{\hat{y}}^{2}\ell}$ is the Hessian of the loss with respect to the network’s outputs, with the expectation taken empirically over the dataset $\mathcal{D}_{\text{cap}}$. Importantly, ${\mathbf{G}}_{\text{cap}}$ is well-behaved for overparameterized and partially trained networks, and lends itself to reliable and scalable approximations which we explore below.

Connections to existing model editing methods. It turns out many existing heuristic model editing methods can be viewed as solving the problem ([2](#S3.E2 "Equation 2 ‣ 3.1 Preserving capabilities with low-curvature updates ‣ 3 CrispEdit: Curvature-Restricted In-Situ Parameter Editing ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing")) via conservative approximations of the quadratic constraint, and with more restrictive assumptions. For example, the popular AlphaEdit technique ([Fang et al., 2025](#bib.bib13)) (and related methods like Adam-NSCL ([Wang et al., 2021](#bib.bib22))) can be viewed as solving the following approximate optimization problem:

|     |                                                                                                                                                                                                                                   |     |     |     |
|-----|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----|-----|-----|
|     | $\begin{array}{cl}                                                                                                                                                                                                                
        & {{{{\min\limits_{\mathbf{θ}}\mathcal{L}_{\text{edit}}}\hspace{0pt}{({\mathbf{θ}})}}\qquad\text{s.t.}\qquad{{{\mathbf{θ}} - {\mathbf{θ}}_{0}} \in {{\mathsf{N}\mathsf{u}\mathsf{l}\mathsf{l}}{({\mathbf{K}}_{\text{cap}})}}}}.}  
       \end{array}$                                                                                                                                                                                                                       |     |     | (4) |

Here, matrix ${\mathbf{K}}_{\text{cap}}$ is constructed from the so-called knowledge vectors for *a particular* MLP layer, used for preserving capabilities in certain domains of interest. We show that AlphaEdit solves a special, more restrictive problem compared to our approach; the proof can be found in Appendix [C](#A3 "Appendix C Proof of Proposition ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing").

###### Proposition 1 (AlphaEdit is more conservative).

Fix an MLP layer $l$ and consider updating only the weights of layer $l$. Let $\mathbf{K}_{\text{cap}}^{l} ≔ {\mathbf{I} \otimes {\lbrack{\mathbf{a}_{l - 1}^{1},\ldots,\mathbf{a}_{l - 1}^{n}}\rbrack}}$ be the layer-input activations on the capability dataset, and $\mathbf{G}_{\text{cap}}^{l}$ be the GNH. Then, ${{\mathsf{N}\mathsf{u}\mathsf{l}\mathsf{l}}{(\mathbf{K}_{\text{cap}}^{l})}} \subseteq {{\mathsf{N}\mathsf{u}\mathsf{l}\mathsf{l}}{(\mathbf{G}_{\text{cap}}^{l})}}$.

Unlike AlphaEdit’s representation-level restriction via ${\mathbf{K}}_{\text{cap}}$, our method preserves capabilities through loss curvatures via ${\mathbf{G}}_{\text{cap}}$. Furthermore, our approach can update multiple layers simultaneously, whereas AlphaEdit edits one layer at a time; consequently, a direct comparison requires matching the edited parameter subset. [Proposition 1](#Thmproposition1 "Proposition 1 (AlphaEdit is more conservative). ‣ 3.2 Gauss-Newton constraint via Bregman divergence ‣ 3 CrispEdit: Curvature-Restricted In-Situ Parameter Editing ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing") shows that even if we artificially restrict our method to a single layer $l$, the feasible update subspace defined by the corresponding layerwise GNH is a *superset* of AlphaEdit’s layerwise subspace. We emphasize that this constraint of the form can be significantly more restrictive than our approach. In particular, ${\mathsf{N}\mathsf{u}\mathsf{l}\mathsf{l}}{({\mathbf{K}}_{\text{cap}})}$ can be a subspace of *much smaller dimension* than the nullspace of the GNH. Furthermore, in contrast to the knowledge matrix, in practice, the GNH is known to be flat in many directions, e.g., due to network overparameterization [Sagun et al. (2017)](#bib.bib36); [Oymak et al. (2019)](#bib.bib34). Therefore, the constraint in AlphaEdit can be significantly more restrictive, leading to a worse tradeoff between preserving prior capabilities and applying the new edits, as evidenced by our comparative analysis in [Section 4.2](#S4.SS2 "4.2 Large-scale LLM evaluations ‣ 4 Experiments ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing").

### 3.3 K-FAC for scalable, matrix-free projections

The remaining obstacle is scale: ${\mathbf{G}}_{\text{cap}}$ is expensive to compute and represent as a matrix. To address this, we approximate ${\mathbf{G}}_{\text{cap}}$ with Kronecker-Factored Approximate Curvature (K-FAC)³³ 3 While K-FAC approximates the Fisher information matrix, for many models, such as the transformers with softmax output and cross-entropy loss, it is equivalent to the GNH ([Martens, 2020](#bib.bib48)). ([Martens and Grosse, 2015](#bib.bib2); [George et al., 2018](#bib.bib1)). At a high level, K-FAC approximates ${\mathbf{G}}_{\text{cap}}$ as a block-diagonal matrix, i.e., ${\mathbf{G}}_{\text{cap}} \approx {{blkdiag}{({\mathbf{G}}_{\text{cap}}^{1},\ldots,{\mathbf{G}}_{\text{cap}}^{L})}}$ for a network with $L$ layers. To describe each block-diagonal approximation, suppose that layer $l$ of an MLP computes its outputs as follows: ${\mathbf{s}}_{l} = {{\mathbf{W}}_{l}\hspace{0pt}{\mathbf{a}}_{l - 1}}$ and ${\mathbf{a}}_{l} = {\phi_{l}\hspace{0pt}{({\mathbf{s}}_{l})}}$, where ${\mathbf{a}}_{l - 1} \in {\mathbb{R}}^{d_{\text{in}}}$ are input activations, ${\mathbf{W}}_{l} \in {\mathbb{R}}^{d_{\text{out}} \times d_{\text{in}}}$ are layer weights (including any bias terms), and ${\mathbf{s}}_{l} \in {\mathbb{R}}^{d_{\text{out}}}$ are layer pre-activations. Let ${\mathbf{g}}_{l} = {\nabla_{{\mathbf{s}}_{l}}\hspace{0pt}\log\hspace{0pt}p\hspace{0pt}{(\hat{y}\mid x)}}$ denote the pseudo-gradients of preactivations. Then, the K-FAC approximation of GNH for layer $l$ is given by:

|     |                                                                                                                                                                                                                                                                                                              |     |     |
|-----|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----|-----|
|     | ${{\mathbf{G}}_{\text{cap}}^{l} \approx {{{\mathbb{E}}\left\lbrack {{\mathbf{a}}_{l - 1}\hspace{0pt}{\mathbf{a}}_{l - 1}^{\top}} \right\rbrack} \otimes {{\mathbb{E}}\left\lbrack {{\mathbf{g}}_{l}\hspace{0pt}{\mathbf{g}}_{l}^{\top}} \right\rbrack}} ≔ {{\mathbf{A}}_{l - 1} \otimes {\mathbf{S}}_{l}}}.$ |     | (5) |

Here, ${\mathbf{A}}_{l - 1}$ and ${\mathbf{S}}_{l}$ are uncentered covariance matrices of the activations and preactivation pseudo-gradients, respectively, with the expectation taken with respect to the capabilities dataset $\mathcal{D}_{\text{cap}}$. This reduces the per-layer storage requirements from $O{({d_{\text{in}}^{2}\hspace{0pt}d_{\text{out}}^{2}})}$ to $O{({d_{\text{in}}^{2} + d_{\text{out}}^{2}})}$ memory.

Matrix-free projections without forming $P_{\gamma}^{(l)}$. Even with K-FAC approximations in place, explicitly materializing a projector matrix ${\mathbf{P}}_{\gamma}^{(l)}$ for the $\gamma$-approximate nullspace of ${\mathbf{G}}_{\text{cap}}^{(l)}$ is memory-prohibitive. Thus, we now describe an efficient method to project onto the $\gamma$-approximate nullspace that does not require explicitly forming ${\mathbf{P}}_{\gamma}^{(l)}$. The key idea behind our approach is the fact that the eigenvalues/eigenvectors of a Kronecker product ${\mathbf{M}} \otimes {\mathbf{N}}$ are simply the product of the eigenvalues/eigenvectors of $\mathbf{M}$ and $\mathbf{N}$. Specifically, let ${\mathbf{A}}_{l - 1} = {{\mathbf{U}}_{\text{in}}\hspace{0pt}\mathbf{\Lambda}_{\text{in}}\hspace{0pt}{\mathbf{U}}_{\text{in}}^{\top}}$ and ${\mathbf{S}}_{l - 1} = {{\mathbf{U}}_{\text{out}}\hspace{0pt}\mathbf{\Lambda}_{\text{out}}\hspace{0pt}{\mathbf{U}}_{\text{out}}^{\top}}$ denote the respective eigendecompositions of ${\mathbf{A}}_{l - 1}$ and ${\mathbf{S}}_{l - 1}$. We show in Appendix [D](#A4 "Appendix D Proof of matrix-free projection ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing"), for a weight-gradient ${\mathbf{Q}}_{l} = {{\nabla_{{\mathbf{W}}_{l}}L_{\text{edit}}}\hspace{0pt}{({\mathbf{θ}})}}$, the projected gradient ${\mathbf{Q}}_{l}^{\text{proj}} = \operatorname{mat}{({\mathbf{P}}_{\gamma}^{(l)}\operatorname{vec}{({\mathbf{Q}}_{l})})}$ can be written as:

|     |                                  |                                                                                                                                                                                                                                                           |     |     |
|-----|----------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----|-----|
|     | ${\mathbf{Q}}_{l}^{\text{proj}}$ | ${\phantom{} = {{\mathbf{U}}_{\text{out}}\hspace{0pt}\left( {\left( {{\mathbf{U}}_{\text{out}}^{\top}\hspace{0pt}{\mathbf{Q}}_{l}\hspace{0pt}{\mathbf{U}}_{\text{in}}} \right) \odot {\mathbf{M}}} \right)\hspace{0pt}{\mathbf{U}}_{\text{in}}^{\top}}},$ |     | (6) |

where $\odot$ denotes the Hadamard (entry-wise) matrix product and ${\mathbf{M}}_{i\hspace{0pt}j} = \left\lbrack \lambda_{i}^{\text{out}}\lambda_{j}^{\text{in}} \leq \lambda_{\gamma} \right\rbrack$ is a binary mask that selects low-curvature components of the Kronecker matrix; $\lambda_{\gamma}$ denotes the largest eigenvalue associated with the $\gamma$-approximate nullspace of ${\mathbf{P}}_{\gamma}^{\ell}$. Using this formula, one never needs to form the ${{d_{\text{in}}\hspace{0pt}d_{\text{out}}} \times d_{\text{in}}}\hspace{0pt}d_{\text{out}}$ projector, further reducing the storage requirement from $O{({d_{\text{in}}^{2}\hspace{0pt}d_{\text{out}}^{2}})}$ to $O{({d_{\text{in}}^{2} + d_{\text{out}}^{2} + {d_{\text{in}}\hspace{0pt}d_{\text{out}}}})}$. ### 3.4 Sequential editing via online projection updates

Up to this point, we have described CrispEdit in a *batch editing setting*, where we assume all the edits $\mathcal{D}_{\text{edit}}$ are gathered at once, and the base model is updated to incorporate all the edits. A complementary setting is one of sequential editing, where edits (single instances or batches) arrive over time and the model is updated from $f_{{\mathbf{θ}}_{0}}$ to $f_{{\mathbf{θ}}_{1}},\ldots,f_{{\mathbf{θ}}_{K}}$ in $K$ successive rounds. Here, at every round $k$, the goal is to preserve both the base capabilities and the earlier edits in rounds $1$ to $k - 1$ applied to the model. This setting is closely connected to continual (or lifelong) learning [De Lange et al. (2021)](#bib.bib32); [Shi et al. (2025)](#bib.bib33) and inherits its core failure mode catastrophic forgetting. Batch editing can be viewed as “breadth-first”, integrating many edits at once, whereas sequential editing is “depth-first”, repeatedly revising the model as the new edit data arrive [Yang et al. (2025b)](#bib.bib24).

Concretely, consider a sequence of edit data that arrives over time in chunks: $\mathcal{D}_{\text{edit}}^{(1)},\ldots,\mathcal{D}_{\text{edit}}^{(K)}$. A naïve algorithm at every round $k$ sets $\mathcal{D}{}_{\text{edit}} = \cup {}_{i = 1}{}^{k}\mathcal{D}{}_{\text{edit}}{}^{(i)}$, and approximately solves problem ([1](#S2.E1 "Equation 1 ‣ 2 The Model editing problem ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing")) using [Algorithm 1](#alg1 "In 3.3 K-FAC for scalable, matrix-free projections ‣ 3 CrispEdit: Curvature-Restricted In-Situ Parameter Editing ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing"). However, this naïve approach must keep all edits around, which can be infeasible and/or impractical for large $K$ or privacy-sensitive settings [Yao et al. (2023)](#bib.bib25). To address these issues, we develop an algorithm ([Algorithm 2](#alg2 "In 3.3 K-FAC for scalable, matrix-free projections ‣ 3 CrispEdit: Curvature-Restricted In-Situ Parameter Editing ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing")) which sequentially maintains the requisite statistics to implement $\gamma$-approximate nullspace projection. The key idea behind [Algorithm 2](#alg2 "In 3.3 K-FAC for scalable, matrix-free projections ‣ 3 CrispEdit: Curvature-Restricted In-Situ Parameter Editing ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing") is that the ${\mathbf{A}}_{l - 1}$ and ${\mathbf{S}}_{l}$ factors from K-FAC (cf. ([5](#S3.E5 "Equation 5 ‣ 3.3 K-FAC for scalable, matrix-free projections ‣ 3 CrispEdit: Curvature-Restricted In-Situ Parameter Editing ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing"))) are memory-efficient sufficient statistics to summarize the approximate nullspace of the capability loss and the previous edit losses. By updating these statistics online after each round $k$, we can simultaneously minimize $\mathcal{L}{({\mathbf{θ}},\mathcal{D}_{\text{edit}}^{(k)})}$ while treating both capabilities and the existing edit losses as hard constraints.

## 4 Experiments

### 4.1 Comparison of various second-order constraints

To understand the effect of various second-order constraints on capability preservation in model editing, we consider a simple setting where calculating the Hessian of the model is tractable. Since this is prohibitive for large LLMs, we use LeNet-5 ([LeCun et al., 2002](#bib.bib27)) as a representative model. We pre-train the model to 99% test accuracy on the MNIST dataset ([LeCun, 1998](#bib.bib28)) and fine-tune it on the Fashion-MNIST dataset ([Xiao et al., 2017](#bib.bib29)). In this setting, we treat the MNIST loss as the capabilities objective, and the Fashion-MNIST loss as the edit objective.

Figure 3: Tradeoff between pre-training accuracy (capability preservation) and post-training performance (edit efficacy) for different nullspace projection methods. We fine-tune a LeNet-5 model pre-trained on MNIST on Fashion-MNIST in the $\gamma$-approximate nullspace of the embeddings (Adam-NSCL) Hessian along with Hessian approximations Gauss-Newton Hessian, K-FAC, and EK-FAC (CrispEdit), over a range of energy thresholds $\gamma$.

For the fine-tuning phase, we first compute the $\gamma$-approximate nullspace projector of the Hessian of the pre-train loss, applying projected gradient descent (PGD) to fine-tune a one hidden-layer MLP, as described in [Section 3.1](#S3.SS1 "3.1 Preserving capabilities with low-curvature updates ‣ 3 CrispEdit: Curvature-Restricted In-Situ Parameter Editing ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing"). To address the inaccuracy of the projector caused by parameter drift, we recalculate the $\gamma$-approximate nullspace projector every time parameter changes more than 25%. To understand the trade-off curve between pre-train and fine-tune test accuracy, we sweep over a range of energy threshold $\gamma = {1 - 10^{- k}}$ with $k \in {\lbrack{\frac{1}{10},7}\rbrack}$. We then compare this algorithm against running PGD onto four alternative approximate nullspaces: (a) activation covariance (cf. Adam-NSCL [Wang et al. (2021)](#bib.bib22)), (b) Gauss-Newton Hessian, (c) K-FAC [Martens and Grosse (2015)](#bib.bib2), and (d) eigenvalue-corrected K-FAC (EK-FAC) [George et al. (2018)](#bib.bib1).

Our results, which illustrate the trade-off between pre-train and fine-tune performance for both the Hessian-based algorithm and the four alternatives (a)-(d), are shown in [Figure 3](#S4.F3 "In 4.1 Comparison of various second-order constraints ‣ 4 Experiments ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing"). We highlight three findings: (i) Projecting gradient updates onto the $\gamma$-approximate nullspace of the Hessian provides an effective strategy for improving fine-tune accuracy on Fashion-MNIST while maintaining base MNIST performance. (ii) The GNH approach yields a trade-off curve that is quite competitive with the Hessian approach, illustrating the efficacy of the Bregman constraint. This, however, is not the case with the activation covariance used by Adam-NSCL. (iii) Both K-FAC and EK-FAC approximate the performance of the GNH approach reasonably well. The last point (iii) is promising, as it suggests that using K-FAC when we are unable to compute the full Hessian (e.g., LLMs) is a viable approach as we demonstrate next.

### 4.2 Large-scale LLM evaluations

We now study scaling CrispEdit to billion-parameter LLMs, predominately focusing on LLaMA-3-8B-Instruct. We investigate the following: (i) How well can we edit the model? (ii) Do the edits generalize for different contexts? (iii) To what extent can we preserve the model capabilities?

Datasets, metrics, and evaluation. We edit the base model on 3000 samples of three standard model editing datasets: ZsRE [Levy et al. (2017)](#bib.bib59), CounterFact [Meng et al. (2022)](#bib.bib9), and WikiBigEdit [Thede et al. (2025)](#bib.bib60). We report two standard edit metrics ([De Cao et al., 2021](#bib.bib31); [Yang et al., 2025a](#bib.bib37)): *reliability* (or efficacy) asks whether the edited model produces an acceptable answer to a given edit query, and *generalization* asks whether the effects of an edit extend to semantically related contexts. All three datasets contain rewrite prompts for efficacy evaluation, and paraphrased prompts for generalization evaluation. To measure capability degradation, we benchmark edited and base models on diverse tasks: MMLU ([Hendrycks et al., 2020](#bib.bib39)), IFEval ([Zhou et al., 2023](#bib.bib40)), TruthfulQA ([Lin et al., 2022](#bib.bib41)), ARC-Challenge ([Clark et al., 2018](#bib.bib42)), and GSM8k ([Cobbe et al., 2021](#bib.bib43)).

An edited LM should apply the edits in a conversational manner and across different contexts. Yet, due to the computational costs, prior works ([Fang et al., 2025](#bib.bib13); [Gu et al., 2025](#bib.bib15)) typically use likelihood-based, teacher-forced evaluation that leak both content and length of the ground truth, leading to overestimated performance ([Yang et al., 2025a](#bib.bib37)). To better capture realistic editing behavior, we follow the WILD evaluation protocol ([Yang et al., 2025a](#bib.bib37)) that combines context-guided autoregressive decoding of LLM responses with LLM-as-a-judge evaluation. We adopt WILD with EasyEdit ([Wang et al., 2024b](#bib.bib38)), evaluating prompts both with and without QA context. While we do not anticipate any real-world carry-over, we include teacher-forced evaluations in [Table 3](#A7.T3 "In Appendix G Additional tables ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing") (Appendix) for completeness.

Method and baselines. We edit the base model with CrispEdit by first computing K-FAC caches on Wikipedia samples for five MLP down-projection layers, and then fine-tuning them with PGD in the $\gamma$-approximate nullspace of caches (cf. [Algorithm 1](#alg1 "In 3.3 K-FAC for scalable, matrix-free projections ‣ 3 CrispEdit: Curvature-Restricted In-Situ Parameter Editing ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing")). We compare against a range of baselines. MEMIT ([Meng et al., 2023](#bib.bib11)) and AlphaEdit ([Fang et al., 2025](#bib.bib13)) follow the locate-then-edit paradigm; Adam-NSCL ([Wang et al., 2021](#bib.bib22)) performs PGD in the feature covariance nullspace; UltraEdit ([Gu et al., 2025](#bib.bib15)) leverages sensitivity analysis with online statistics; MEND ([Mitchell et al., 2022a](#bib.bib18)) uses a hypernetwork to predict parameter changes, FT and LoRA ([Hu et al., 2022](#bib.bib44); [Zhang et al., 2023](#bib.bib45)) performs standard and low-rank fine-tuning, respectively; and LocBF-FT ([Yang et al., 2025b](#bib.bib24)) constrains fine-tuning to a single, hyperparameter-tuned layer. For more details about the evaluation and baselines, see Appendix [E](#A5 "Appendix E Additional details on LLM experiments ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing").

Figure 4: Runtime comparison of CrispEdit with other methods. We apply a number of model editing methods to edit LLaMA-3-8B-Instruct on 3,000 ZsRE samples and measure the wall-clock time for execution.

Key results. We report our key results in [Table 1](#S4.T1 "In 4.1 Comparison of various second-order constraints ‣ 4 Experiments ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing"). Across all datasets, we find two consistent patterns. First, aggressive editing approaches—including MEMIT, MEND, FT, and Adam-NSCL—exhibit substantial degradation. While these methods perform well under teacher-forced evaluation (cf. [Table 3](#A7.T3 "In Appendix G Additional tables ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing"), Appendix), the degraded base capabilities adversely affect their editing performance under autoregressive decoding (cf. Appendix [F](#A6 "Appendix F Qualitative case study ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing")). Second, conservative editing strategies, which restrict updates to limited parameter subspaces, better preserve base capabilities but lead to a suboptimal edited capabilities. AlphaEdit remains a strong baseline of this class, yet it degrades the model’s base capabilities due to its limited nullspace estimate, in addition to needing additional subject-centric representations. In comparison, CrispEdit consistently tops editing performance while preserving the base capabilities nearly intact. Furthermore, it remains computationally efficient (cf. [Figure 4](#S4.F4 "In 4.2 Large-scale LLM evaluations ‣ 4 Experiments ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing")), as it only augments standard fine-tuning with PGD.

(i) Robustness to energy threshold $\gamma$. We vary the threshold $\gamma$ from 0.5 to 0.99. [Table 8](#A7.T8 "In Appendix G Additional tables ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing") shows that CrispEdit’s base capability preservation is reasonably robust to the threshold, even with $\gamma$ as small as $0.5$.

(ii) Sensitivity to the size of capability dataset $n$. We vary $n = {|\mathcal{D}_{\text{cap}}|}$ from 10 to 100,000. To validate the importance of capability dataset, we run standard finetuning with no projections (i.e., $n = 0$). As [Figure 5](#S4.F5 "In 4.2 Large-scale LLM evaluations ‣ 4 Experiments ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing") shows, while CrispEdit is robust to $n$, lack of projection yields a detrimental effect on capability preservation. Furthermore, capability preservation can improve edit performance in autoregressive evaluation through maintaining fluency and reliable instruction-following during generation.

## 5 Related work

Memory-based approaches employ additional memory components to store edits outside its parameters. These components can be in the form of axillary models ([Dong et al., 2022](#bib.bib3); [Mitchell et al., 2022b](#bib.bib4); [Hartvigsen et al., 2023](#bib.bib5); [Wang et al., 2024a](#bib.bib7)), in-context learning ([Wang et al., 2024a](#bib.bib7), WISE), low-rank adapters ([Yu et al., 2024](#bib.bib6), MELO), or retrieval-based alignment ([Jiang et al., 2024](#bib.bib8), LTE). Compared to these methods, CrispEdit does not assume any data, memory, or architectural augmentations for inference.

Locate-then-edit based approaches aim to locate a set of parameters responsible for a undesired behavior and edit them. They rely on the assumption that feed-forward networks contain the knowledge in models ([Geva et al., 2021](#bib.bib16); [Geva et al., 2022](#bib.bib17); [Dai et al., 2022](#bib.bib10)) and precisely edit the neurons responsible for particular information. They often assume structures in the dataset such as subject or entity ([Meng et al., 2022](#bib.bib9); [Meng et al., 2023](#bib.bib11); [Gupta et al., 2024](#bib.bib12); [Fang et al., 2025](#bib.bib13); [Pan et al., 2025](#bib.bib14)) and relations ([Dai et al., 2022](#bib.bib10)). An exception to these is [Gu et al. (2025, UltraEdit)](#bib.bib15), which uses representations of the last token for its localization calculation. In contrast, CrispEdit does not assume any edit structure and does not require locating specific parameters.

Hypernet-based approaches treat predicting parameters shifts as a meta-learning problem and learns a separate network to solve the problem. These methods take the underlying optimization problem of locate-then-edit methods and uses an hypernetwork to predict the parameter shifts, such as [Mitchell et al. (2022a, MEND)](#bib.bib18) solving the optimization speed of [Meng et al. (2022, ROME)](#bib.bib9) and [Tan et al. (2024, MALMEN)](#bib.bib19) solving the least squares problem of [Meng et al. (2023, MEMIT)](#bib.bib11). Recently, [Li et al. (2025, RLEdit)](#bib.bib20) treats the dual optimization problem of model stability and edit quality by treating the hypernetwork as a reinforcement learning (RL) agent. Compared to these methods, CrispEdit has no additional network for predicting parameters shifts.

Constrained fine-tuning approaches perform GD-based finetuning with additional constraints such as weight decay ([Rawat et al., 2021](#bib.bib21), FT-L), null-space projection ([Wang et al., 2021](#bib.bib22), Adam-NSCL), prompt-masking ([Zhang et al., 2024](#bib.bib23), FT-M), low-rank update ([Yu et al., 2024](#bib.bib6), MELO) or strict layer choice ([Yang et al., 2025b](#bib.bib24), LocBF-FT). CrispEdit builds on this line by combining FT-M with PGD, deriving the projection from a constrained-optimization view of capability preservation leveraging the loss curvature. In this way, CrispEdit aims to reduce the amount of manual strictness (e.g., highly restrictive layer choices or aggressive update limitations) sometimes required for constrained fine-tuning baselines, while retaining the simplicity and scalability of standard fine-tuning. Closest to our method is Adam-NSCL, which applies PGD in the null space of activation covariances. We show that Adam-NSCL is a special, more conservative case ([Proposition 1](#Thmproposition1 "Proposition 1 (AlphaEdit is more conservative). ‣ 3.2 Gauss-Newton constraint via Bregman divergence ‣ 3 CrispEdit: Curvature-Restricted In-Situ Parameter Editing ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing")) and CrispEdit empirically outperforms it.

Continual learning (CL) is closely related to model editing that studies sequential updates while mitigating catastrophic forgetting. Existing methods broadly fall into three categories: regularization-based methods aim to preserve relevant parameters ([Zenke et al., 2017](#bib.bib49)), replay-based methods aim to efficiently replay past memories during training ([Shin et al., 2017](#bib.bib50); [Rebuffi et al., 2017](#bib.bib52)), and architecture-based methods adjust model architecture on the fly ([Rusu et al., 2016](#bib.bib51)). Relevant to our work are curvature aware methods, most notably elastic weight consolidation ([Kirkpatrick et al., 2017](#bib.bib46), EWC), which estimates old task curvature with the Fisher and adds it as a penalty alongside standard loss to minimize curvature change. Relatedly, [Li et al. (2024, HALRP)](#bib.bib47) performs automatic rank selection with Hessian information of the loss w.r.t base weights and low rank perturbation on the weights to obtain task weights. Recently, [Gupta et al. (2024)](#bib.bib12) unify different CL methods under a single Bregman divergence-based objective. In comparison, CrispEdit avoids per-step auxiliary loss calculation and scales to LLM editing.

## 6 Conclusion and future work

We formulate model editing as a quadratically constrained optimization problem, introducing CrispEdit and its sequential variant as scalable approaches for editing billion-parameter LLMs while preserving capabilities. Our method leverages Gauss–Newton Hessian eigenspaces, induced by a Bregman divergence constraint, to identify low-curvature directions where the capabilities loss is nearly invariant. We use K-FAC to design efficient projection onto these nullspaces, making CrispEdit practical at LLM scale.

Our work opens up several exciting avenues for future work. The first direction is exploring the use of CrispEdit in other applications, such as safety (e.g., editing out harmful generation and/or hallucinations) and personalization (e.g., changing response style to suit user preferences). Another interesting direction is to utilize CrispEdit for learning interpretable models, e.g., training models to minimize some notion of model complexity such as weight sparsity, feature disentanglement, etc., subject to maintaining model capabilities. Finally, on the algorithmic side, alternative techniques for non-linear constrained optimization, such as trust-region and sequential quadratic programming methods, could enable CrispEdit to take larger, more aggressive fine-tuning steps leading to further improvements on edit capabilities while preserving base capabilities.

## Appendix A Notation

General notations. We use bold lowercase letters (e.g., $\mathbf{θ}$) for vectors and bold uppercase letters (e.g., $\mathbf{H}$) for matrices. For a matrix $\mathbf{M}$, ${\mathsf{N}\mathsf{u}\mathsf{l}\mathsf{l}}{({\mathbf{M}})}$ denotes its null space. The identity matrix is denoted by $\mathbf{I}$. For vectors ${\mathbf{u}},{\mathbf{v}}$, $\langle{{\mathbf{u}},{\mathbf{v}}}\rangle$ denotes the standard inner product. The operator $\odot$ denotes the Hadamard (element-wise) product. We denote sets by calligraphy letters e.g., $\mathcal{X}$. We write ${{\mathbb{E}}_{\mathcal{D}}\hspace{0pt}{\lbrack{\phi{(z)}}\rbrack}} = {\frac{1}{n}\hspace{0pt}{\sum_{i}{\phi{(z_{i})}}}}$ to denote the empirical expectation of function $\phi{(z)}$ using the dataset $\mathcal{D} = {\{ z_{i}\}}_{i = 1}^{n}$. $\otimes$ denotes the Kronecker product. For a subspace $S \subseteq {\mathbb{R}}^{d}$, $P_{S} \in {\mathbb{R}}^{d \times d}$ denotes the orthogonal projection onto $S$.

Models and parameters. Let $f_{\mathbf{θ}}:{\mathcal{X}\rightarrow\mathcal{Y}}$ denote a parametric model with parameters ${\mathbf{θ}} \in \Theta \subseteq {\mathbb{R}}^{p}$. The pretrained (base) model parameters are denoted by ${\mathbf{θ}}_{0}$. We write ${\Delta\hspace{0pt}{\mathbf{θ}}}:={{\mathbf{θ}} - {\mathbf{θ}}_{0}}$ for parameter updates.

Datasets. We distinguish between: (i) a *capability dataset* $\mathcal{D}_{cap} = {\{{(x_{i},y_{i})}\}}_{i = 1}^{n}$, used as a proxy for behaviors to be preserved, and (ii) an *edit dataset* $\mathcal{D}_{edit} = {\{{(x_{i},y_{i})}\}}_{i = 1}^{T}$, specifying desired edits. Typically $n \gg T$.

Losses and objectives. Let $\ell{(\hat{y},y)}$ denote a task-appropriate loss (e.g., cross-entropy). The empirical capability loss is

|     |                                                                                                                                                                             |     |
|-----|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----|
|     | $${{\mathcal{L}_{cap}\hspace{0pt}{({\mathbf{θ}})}} = {\frac{1}{n}\hspace{0pt}{\sum\limits_{i = 1}^{n}{\ell\left( {f_{\mathbf{θ}}\hspace{0pt}{(x_{i})}},y_{i} \right)}}}},$$ |     |

and $\mathcal{L}_{edit}\hspace{0pt}{({\mathbf{θ}})}$ denotes the edit loss evaluated on $\mathcal{D}_{edit}$. We measure deviations in capability loss using a distance function $\mathsf{d}{( \cdot , \cdot )}$, including absolute loss differences and Bregman divergences.

Second-order quantities. We denote by

|     |                                                                                                                |     |
|-----|----------------------------------------------------------------------------------------------------------------|-----|
|     | $${\mathbf{H}}_{cap}:={\nabla_{\mathbf{θ}}^{2}\hspace{0pt}\mathcal{L}_{cap}\hspace{0pt}{({\mathbf{θ}}_{0})}}$$ |     |

the Hessian of the capability loss at the base model parameters. When using Bregman divergences, the quadratic approximation is governed by the *Gauss–Newton Hessian (GNH)*,

|     |                                                                                                                                                                                                  |     |
|-----|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----|
|     | $${{\mathbf{G}}_{cap}:={{\mathbb{E}}_{{(x,y)} \sim \mathcal{D}_{cap}}\hspace{0pt}\left\lbrack {{\mathbf{J}}^{\top}\hspace{0pt}{\mathbf{H}}_{\hat{y}}\hspace{0pt}{\mathbf{J}}} \right\rbrack}},$$ |     |

where ${\mathbf{J}} = {{\nabla_{\mathbf{θ}}f_{\mathbf{θ}}}\hspace{0pt}{(x)}}$ is the parameter–output Jacobian and ${\mathbf{H}}_{\hat{y}} = {\nabla_{\hat{y}}^{2}\ell}$ is the Hessian of the loss with respect to model outputs.

Low-curvature subspaces. Let ${\mathbf{M}} \in {\{{\mathbf{H}}_{cap},{\mathbf{G}}_{cap}\}}$ admit an eigendecomposition ${\mathbf{M}} = {{\mathbf{U}}\hspace{0pt}\mathbf{\Sigma}\hspace{0pt}{\mathbf{U}}^{\top}}$, with eigenvalues $\sigma_{1} \geq \cdots \geq \sigma_{p} \geq 0$. For a threshold $\gamma \in {(0,1)}$, we define $k$ as the smallest index such that

|     |                                                                                                           |     |
|-----|-----------------------------------------------------------------------------------------------------------|-----|
|     | $${\left. {\sum\limits_{i = 1}^{k}\sigma_{i}}/{\sum\limits_{i = 1}^{p}\sigma_{i}} \right. \geq \gamma}.$$ |     |

The $\gamma$-approximate nullspace is spanned by ${\mathbf{U}}_{\phantom{} > k} = {\lbrack{{\mathbf{u}}_{k + 1},\ldots,{\mathbf{u}}_{p}}\rbrack}$, and the corresponding projector is

|     |                                                                                                               |     |
|-----|---------------------------------------------------------------------------------------------------------------|-----|
|     | $${{\mathbf{P}}_{\gamma}:={{\mathbf{U}}_{\phantom{} > k}\hspace{0pt}{\mathbf{U}}_{\phantom{} > k}^{\top}}}.$$ |     |

Layerwise notation and K-FAC. For an MLP layer $\ell$, we denote input activations by ${\mathbf{a}}_{\ell - 1}$, weights by ${\mathbf{W}}_{\ell} \in {\mathbb{R}}^{d_{out} \times d_{in}}$, and pre-activation pseudo-gradients by ${\mathbf{g}}_{\ell}$. Under the K-FAC approximation, the layerwise GNH block is approximated as

|     |                                                                                                  |     |
|-----|--------------------------------------------------------------------------------------------------|-----|
|     | $${{\mathbf{G}}_{cap}^{(\ell)} \approx {{\mathbf{A}}_{\ell - 1} \otimes {\mathbf{S}}_{\ell}}},$$ |     |

where ${\mathbf{A}}_{\ell - 1} = {{\mathbb{E}}{\lbrack{{\mathbf{a}}_{\ell - 1}\hspace{0pt}{\mathbf{a}}_{\ell - 1}^{\top}}\rbrack}}$ and ${\mathbf{S}}_{\ell} = {{\mathbb{E}}{\lbrack{{\mathbf{g}}_{\ell}\hspace{0pt}{\mathbf{g}}_{\ell}^{\top}}\rbrack}}$.

Operators. We use $\operatorname{vec}{( \cdot )}$ and $\operatorname{mat}{( \cdot )}$ to denote vectorization and reshaping operators between matrix and vector forms.

## Appendix B Proof of Bregman divergence quadratic form

The following lemma computes a second order approximation to Bregman divergence associated with a loss function $\ell$.

###### Proposition 2 (Quadratic Approximation of Bregman Divergence).

Fix an input $\mathbf{x}$ and parameters ${\mathbf{θ}}_{0} \in {\mathbb{R}}^{p}$. Assume ${\mathbf{f}_{\mathbf{θ}}\hspace{0pt}{(\mathbf{x})}}:{\mathcal{X}\rightarrow{\mathbb{R}}^{m}}$ is $C^{2}$ in $\mathbf{θ}$ and $\ell:{{\mathbb{R}}^{m}\rightarrow{\mathbb{R}}}$ is convex and $C^{2}$. Define the Bregman divergence

|     |                                                                                                                                                                                                           |     |     |
|-----|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----|-----|
|     | ${{D_{\ell}\hspace{0pt}{({\mathbf{a}},{\mathbf{b}})}} = {{\ell{({\mathbf{a}})}} - {\ell{({\mathbf{b}})}} - {\langle{{{\nabla\ell}\hspace{0pt}{({\mathbf{b}})}},{{\mathbf{a}} - {\mathbf{b}}}}\rangle}}}.$ |     | (7) |

Denote the Jacobian by ${\mathbf{J}{({\mathbf{θ}})}}:={{\nabla_{\mathbf{θ}}\mathbf{f}_{\mathbf{θ}}}\hspace{0pt}{(\mathbf{x})}} \in {\mathbb{R}}^{m \times p}$ and the output Hessian by ${\mathbf{H}_{\ell}\hspace{0pt}{(\mathbf{u})}}:={{\nabla_{\mathbf{u}}^{2}\ell}\hspace{0pt}{(\mathbf{u})}} \in {\mathbb{R}}^{m \times m}$. Then, there exists $\rho > 0$ such that for all $\Delta\hspace{0pt}{\mathbf{θ}}$ with ${|{\Delta\hspace{0pt}{\mathbf{θ}}}|} \leq \rho$

|     |                                                                                                                                                                                                     |                                                                                                                                                                                                                                                                                                                                                                                                                                                             |     |
|-----|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----|
|     | $D_{\ell}\hspace{0pt}\left( {{\mathbf{f}}_{{\mathbf{θ}}_{0} + {\Delta\hspace{0pt}{\mathbf{θ}}}}\hspace{0pt}{({\mathbf{x}})}},{{\mathbf{f}}_{{\mathbf{θ}}_{0}}\hspace{0pt}{({\mathbf{x}})}} \right)$ | ${\phantom{} = {{\frac{1}{2}\hspace{0pt}\Delta\hspace{0pt}{\mathbf{θ}}^{\top}\hspace{0pt}\left\lbrack {{\mathbf{J}}\hspace{0pt}{({\mathbf{θ}}_{0})}^{\top}\hspace{0pt}{\mathbf{H}}_{\ell}\hspace{0pt}\left( {{\mathbf{f}}_{{\mathbf{θ}}_{0}}\hspace{0pt}{({\mathbf{x}})}} \right)\hspace{0pt}{\mathbf{J}}\hspace{0pt}{({\mathbf{θ}}_{0})}} \right\rbrack\hspace{0pt}\Delta\hspace{0pt}{\mathbf{θ}}} + {o{({\|{\Delta\hspace{0pt}{\mathbf{θ}}}\|}^{2})}}}}.$ |     |

###### Proof.

By the chain rule,

|     |                                                                                                                                                                                 |                                                                                                                                                                                                                                                                                     |     |
|-----|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----|
|     | ${\nabla_{\mathbf{θ}}D_{\ell}}\hspace{0pt}\left( {{\mathbf{f}}_{\mathbf{θ}}\hspace{0pt}{({\mathbf{x}})}},{{\mathbf{f}}_{{\mathbf{θ}}_{0}}\hspace{0pt}{({\mathbf{x}})}} \right)$ | ${\phantom{} = {{\mathbf{J}}\hspace{0pt}{({\mathbf{θ}})}^{\top}\hspace{0pt}\left( {{{\nabla\ell}\hspace{0pt}{({{\mathbf{f}}_{\mathbf{θ}}\hspace{0pt}{({\mathbf{x}})}})}} - {{\nabla\ell}\hspace{0pt}{({{\mathbf{f}}_{{\mathbf{θ}}_{0}}\hspace{0pt}{({\mathbf{x}})}})}}} \right)}},$ |     |

which evaluates to zero at ${\mathbf{θ}} = {\mathbf{θ}}_{0}$. Differentiating again gives the following decomposition:

|     |                                                                                                                                                                                     |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |     |
|-----|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----|
|     | ${\nabla_{\mathbf{θ}}^{2}D_{\ell}}\hspace{0pt}\left( {{\mathbf{f}}_{\mathbf{θ}}\hspace{0pt}{({\mathbf{x}})}},{{\mathbf{f}}_{{\mathbf{θ}}_{0}}\hspace{0pt}{({\mathbf{x}})}} \right)$ | ${\phantom{} = {{{\mathbf{J}}\hspace{0pt}{({\mathbf{θ}})}^{\top}\hspace{0pt}{\mathbf{H}}_{\ell}\hspace{0pt}\left( {{\mathbf{f}}_{\mathbf{θ}}\hspace{0pt}{({\mathbf{x}})}} \right)\hspace{0pt}{\mathbf{J}}\hspace{0pt}{({\mathbf{θ}})}} + {\sum\limits_{j = 1}^{m}{\left( \left. \left\lbrack {{\nabla_{\mathbf{a}}D_{\ell}}\hspace{0pt}{({\mathbf{a}},{{\mathbf{f}}_{{\mathbf{θ}}_{0}}\hspace{0pt}{({\mathbf{x}})}})}} \right\rbrack_{j} \right|_{{\mathbf{a}} = {{\mathbf{f}}_{\mathbf{θ}}\hspace{0pt}{({\mathbf{x}})}}} \right)\hspace{0pt}{\nabla_{\mathbf{θ}}^{2}{\lbrack{{\mathbf{f}}_{\mathbf{θ}}\hspace{0pt}{({\mathbf{x}})}}\rbrack}_{j}}}}}}.$ |     |

At ${\mathbf{θ}} = {\mathbf{θ}}_{0}$, ${{\nabla_{\mathbf{a}}D_{\ell}}\hspace{0pt}\left( {{\mathbf{f}}_{{\mathbf{θ}}_{0}}\hspace{0pt}{({\mathbf{x}})}},{{\mathbf{f}}_{{\mathbf{θ}}_{0}}\hspace{0pt}{({\mathbf{x}})}} \right)} = 0$ and thus the second term in the above equation evaluates to zero. Therefore,

|     |                                                                                                                                                                                                                                        |                                                                                                                                                                                                                                                        |     |
|-----|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----|
|     | $\left. {{\nabla_{\mathbf{θ}}^{2}D_{\ell}}\hspace{0pt}\left( {{\mathbf{f}}_{\mathbf{θ}}\hspace{0pt}{({\mathbf{x}})}},{{\mathbf{f}}_{{\mathbf{θ}}_{0}}\hspace{0pt}{({\mathbf{x}})}} \right)} \right|_{{\mathbf{θ}} = {\mathbf{θ}}_{0}}$ | ${\phantom{} = {{\mathbf{J}}\hspace{0pt}{({\mathbf{θ}}_{0})}^{\top}\hspace{0pt}{\mathbf{H}}_{\ell}\hspace{0pt}\left( {{\mathbf{f}}_{{\mathbf{θ}}_{0}}\hspace{0pt}{({\mathbf{x}})}} \right)\hspace{0pt}{\mathbf{J}}\hspace{0pt}{({\mathbf{θ}}_{0})}}}.$ |     |

Thus, by the second order Taylor approximation of $D_{\ell}\hspace{0pt}{({{\mathbf{f}}_{\mathbf{θ}}\hspace{0pt}{({\mathbf{x}})}},{{\mathbf{f}}_{{\mathbf{θ}}_{0}}\hspace{0pt}{({\mathbf{x}})}})}$ around ${\mathbf{θ}}_{0}$, we conclude

|     |                                                                                                                                                                                                     |                                                                                                                                                                                                                                                                                                                                                                                                                                                             |     |
|-----|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----|
|     | $D_{\ell}\hspace{0pt}\left( {{\mathbf{f}}_{{\mathbf{θ}}_{0} + {\Delta\hspace{0pt}{\mathbf{θ}}}}\hspace{0pt}{({\mathbf{x}})}},{{\mathbf{f}}_{{\mathbf{θ}}_{0}}\hspace{0pt}{({\mathbf{x}})}} \right)$ | ${\phantom{} = {{\frac{1}{2}\hspace{0pt}\Delta\hspace{0pt}{\mathbf{θ}}^{\top}\hspace{0pt}\left\lbrack {{\mathbf{J}}\hspace{0pt}{({\mathbf{θ}}_{0})}^{\top}\hspace{0pt}{\mathbf{H}}_{\ell}\hspace{0pt}\left( {{\mathbf{f}}_{{\mathbf{θ}}_{0}}\hspace{0pt}{({\mathbf{x}})}} \right)\hspace{0pt}{\mathbf{J}}\hspace{0pt}{({\mathbf{θ}}_{0})}} \right\rbrack\hspace{0pt}\Delta\hspace{0pt}{\mathbf{θ}}} + {o{({\|{\Delta\hspace{0pt}{\mathbf{θ}}}\|}^{2})}}}}.$ |     |

∎

We show that any vectors that belong to the null space of ${\mathbf{K}}_{cap}$ also belongs to the null space of ${\mathbf{G}}_{cap}$. We interpret ${\Delta\hspace{0pt}{\mathbf{W}}_{\ell}} \in {{Null}{({\mathbf{K}}_{cap}^{\ell})}}$ as the constraint ${\Delta\hspace{0pt}{\mathbf{W}}_{\ell}\hspace{0pt}{\mathbf{K}}_{cap}^{\ell}} = 0$ (equivalently, ${{({{({\mathbf{K}}_{cap}^{\ell})}^{\top} \otimes {\mathbf{I}}_{d_{out}}})}\hspace{0pt}{vec}\hspace{0pt}{({\Delta\hspace{0pt}{\mathbf{W}}_{\ell}})}} = 0$ under column-wise vectorization). We keep all network parameters fixed except the layer-$\ell$ weight matrix ${\mathbf{W}} \in {\mathbb{R}}^{d_{out} \times d_{in}}$. Define the parameter-space representation of layer-$\ell$ weights and updates by ${{\mathbf{w}} ≔ {{vec}{({\mathbf{W}})}} \in {\mathbb{R}}^{d_{out}\hspace{0pt}d_{in}}},$ and ${{\Delta\hspace{0pt}{\mathbf{w}}} ≔ {{vec}{({\Delta\hspace{0pt}{\mathbf{W}}})}} \in {\mathbb{R}}^{d_{out}\hspace{0pt}d_{in}}}.$ Define the downstream map $f:{{\mathbb{R}}^{d_{out}}\rightarrow{\mathbb{R}}^{m}}$ to be the function that takes the layer pre-activation ${\mathbf{s}}_{\ell}$ at layer $\ell$ (with all other parameters held fixed) to the network output. Thus, for each capability example $i \in {\lbrack n\rbrack}$,

|     |                                                                                                                                         |     |
|-----|-----------------------------------------------------------------------------------------------------------------------------------------|-----|
|     | ${{{\mathbf{y}}^{i}\hspace{0pt}{({\mathbf{W}})}} = {f{({{\mathbf{W}}\hspace{0pt}{\mathbf{a}}_{\ell - 1}^{i}})}} \in {\mathbb{R}}^{m}}.$ |     |

Let ${{\mathbf{J}}_{f}\hspace{0pt}{({\mathbf{s}}_{\ell})}} ≔ {{\nabla_{{\mathbf{s}}_{\ell}}f}\hspace{0pt}{({\mathbf{s}}_{\ell})}} \in {\mathbb{R}}^{m \times d_{out}}$ denote the Jacobian of $f$ at ${\mathbf{s}}_{\ell}$. By the chain rule,

|     |                                                                         |                                                                                                                                                                                                                                                          |     |
|-----|-------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----|
|     | ${\nabla_{\mathbf{w}}{\mathbf{y}}^{i}}\hspace{0pt}{({\mathbf{W}}_{0})}$ | ${\phantom{} = \left. {{\mathbf{J}}_{f}\hspace{0pt}{({{\mathbf{W}}_{0}\hspace{0pt}{\mathbf{a}}_{\ell - 1}^{i}})}\hspace{0pt}{\nabla_{\mathbf{w}}{({{\mathbf{W}}\hspace{0pt}{\mathbf{a}}_{\ell - 1}^{i}})}}} \right|_{{\mathbf{W}} = {\mathbf{W}}_{0}}}.$ |     |

The map ${\mathbf{W}}\mapsto{{\mathbf{W}}\hspace{0pt}{\mathbf{a}}_{\ell - 1}^{i}}$ is linear, and its Jacobian under ${\mathbf{w}} = {{vec}{({\mathbf{W}})}}$ is

|     |                                                                                                                                                               |     |
|-----|---------------------------------------------------------------------------------------------------------------------------------------------------------------|-----|
|     | ${{\nabla_{\mathbf{w}}{({{\mathbf{W}}\hspace{0pt}{\mathbf{a}}_{\ell - 1}^{i}})}} = {{\mathbf{I}}_{d_{out}} \otimes {({\mathbf{a}}_{\ell - 1}^{i})}^{\top}}},$ |     |

so the per-example Jacobian with respect to $\mathbf{w}$ can be written as

|     |                                                                                                                                                                                                                                                                                                 |     |
|-----|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----|
|     | ${{\mathbf{J}}_{i} ≔ {{\nabla_{\mathbf{w}}{\mathbf{y}}^{i}}\hspace{0pt}{({\mathbf{W}}_{0})}} = {{\mathbf{J}}_{f}\hspace{0pt}{({{\mathbf{W}}_{0}\hspace{0pt}{\mathbf{a}}_{\ell - 1}^{i}})}\hspace{0pt}\left( {{\mathbf{I}}_{d_{out}} \otimes {({\mathbf{a}}_{\ell - 1}^{i})}^{\top}} \right)}}.$ |     |

Now let ${\Delta\hspace{0pt}{\mathbf{W}}} \in {{\mathsf{N}\mathsf{u}\mathsf{l}\mathsf{l}}{({\mathbf{K}}_{cap})}}$, i.e. ${\Delta\hspace{0pt}{\mathbf{W}}\hspace{0pt}{\mathbf{a}}_{\ell - 1}^{i}} = \mathbf{0}$ for all $i \in {\lbrack n\rbrack}$. Using the identity

|     |                                                                                                                                                                                                                                                              |     |
|-----|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----|
|     | ${{{\left( {{\mathbf{I}}_{d_{out}} \otimes {\mathbf{x}}^{\top}} \right)\hspace{0pt}\Delta\hspace{0pt}{\mathbf{w}}} = {\Delta\hspace{0pt}{\mathbf{W}}\hspace{0pt}{\mathbf{x}}}}\qquad{{\text{for any~}\hspace{0pt}{\mathbf{x}}} \in {\mathbb{R}}^{d_{in}}}},$ |     |

we obtain

|     |                                                                                                                                                                                                                                                                                   |     |
|-----|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----|
|     | ${{{\left( {{\mathbf{I}}_{d_{out}} \otimes {({\mathbf{a}}_{\ell - 1}^{i})}^{\top}} \right)\hspace{0pt}\Delta\hspace{0pt}{\mathbf{w}}} = {\Delta\hspace{0pt}{\mathbf{W}}\hspace{0pt}{\mathbf{a}}_{\ell - 1}^{i}} = \mathbf{0}}\mspace{39mu}{{\forall i} \in {\lbrack n\rbrack}}},$ |     |

and hence ${{\mathbf{J}}_{i}\hspace{0pt}\Delta\hspace{0pt}{\mathbf{w}}} = \mathbf{0}$ for all $i$. By definition, the layer Gauss–Newton Hessian for the capability objective has the form

|     |                                                                                                                                      |     |
|-----|--------------------------------------------------------------------------------------------------------------------------------------|-----|
|     | ${{\mathbf{G}}_{cap} = {\sum\limits_{i = 1}^{n}{{\mathbf{J}}_{i}^{\top}\hspace{0pt}{\mathbf{H}}_{i}\hspace{0pt}{\mathbf{J}}_{i}}}},$ |     |

where each ${\mathbf{H}}_{i} \succeq \mathbf{0}$. Therefore, for any vector $\mathbf{v}$,

|     |                                                                                                                                                                                                                                                           |     |
|-----|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----|
|     | ${{{\mathbf{v}}^{\top}\hspace{0pt}{\mathbf{G}}_{cap}\hspace{0pt}{\mathbf{v}}} = {\sum\limits_{i = 1}^{n}{{({{\mathbf{J}}_{i}\hspace{0pt}{\mathbf{v}}})}^{\top}\hspace{0pt}{\mathbf{H}}_{i}\hspace{0pt}{({{\mathbf{J}}_{i}\hspace{0pt}{\mathbf{v}}})}}}},$ |     |

so if ${{\mathbf{J}}_{i}\hspace{0pt}{\mathbf{v}}} = \mathbf{0}$ for all $i$ then ${{\mathbf{v}}^{\top}\hspace{0pt}{\mathbf{G}}_{cap}\hspace{0pt}{\mathbf{v}}} = 0$, which implies ${{\mathbf{G}}_{cap}\hspace{0pt}{\mathbf{v}}} = \mathbf{0}$ since ${\mathbf{G}}_{cap} \succeq \mathbf{0}$. Applying this with ${\mathbf{v}} = {\Delta\hspace{0pt}{\mathbf{w}}}$ and using ${{\mathbf{J}}_{i}\hspace{0pt}\Delta\hspace{0pt}{\mathbf{w}}} = \mathbf{0}$ for all $i$, we conclude ${{\mathbf{G}}_{cap}\hspace{0pt}\Delta\hspace{0pt}{\mathbf{w}}} = \mathbf{0}$, i.e. ${\Delta\hspace{0pt}{\mathbf{W}}} \in {{\mathsf{N}\mathsf{u}\mathsf{l}\mathsf{l}}{({\mathbf{G}}_{cap})}}$.

## Appendix D Proof of matrix-free projection

###### Proposition 3.

Let $\mathbf{A} \in {\mathbb{R}}^{n_{A} \times n_{A}}$, $\mathbf{B} \in {\mathbb{R}}^{n_{B} \times n_{B}}$ be two positive semi-definite matrices, $\mathbf{C}:={\mathbf{B} \otimes \mathbf{A}}$ denote the Kronecker product, and let $\mathbf{X} \in {\mathbb{R}}^{n_{A} \times n_{B}}$. Let $\tau:{{\mathbb{R}}_{\phantom{} \geq 0}\mapsto{\{ 0,1\}}}$ denote any predicate function, and define the following subspace:

|     |                                                                                                                                                                                                                        |     |
|-----|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----|
|     | $${S:={{span}{\{{{\mathbf{u}} \in {\mathbb{R}}^{n_{A}\hspace{0pt}n_{B}}}\mid{\text{the pair~}{(\lambda,{\mathbf{u}})}\text{~is an eigenvalue/vector pair of~}{\mathbf{C}}\text{~with~}{{\tau{(\lambda)}} = 1}}\}}}}.$$ |     |

We have that:

|     |                                                                                                                                                                                                                |     |     |
|-----|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----|-----|
|     | $\operatorname{mat}{({\mathbf{P}}_{S}\operatorname{vec}{({\mathbf{X}})})} = {\mathbf{U}}_{A}\left( {({\mathbf{U}}_{A}^{\top}{\mathbf{X}}{\mathbf{U}}_{B})} \odot {\mathbf{M}} \right){\mathbf{U}}_{B}^{\top},$ |     | (8) |

where $\mathbf{A} = {\mathbf{U}_{A}\hspace{0pt}{diag}\hspace{0pt}{(\lambda_{A,1},\ldots,\lambda_{A,n_{A}})}\hspace{0pt}\mathbf{U}_{A}^{\top}}$ and $\mathbf{B} = {\mathbf{U}_{B}\hspace{0pt}{diag}\hspace{0pt}{(\lambda_{B,1},\ldots,\lambda_{B,n_{B}})}\hspace{0pt}\mathbf{U}_{B}^{\top}}$ are the eigen-decompositions of $\mathbf{A},\mathbf{B}$ respectively, and $\mathbf{M} \in {\mathbb{R}}^{n_{A} \times n_{B}}$ with $M_{i\hspace{0pt}j} = {\tau{({\lambda_{A,i} \cdot \lambda_{B,j}})}}$ is the mask matrix corresponding to the predicate function $\tau$.

Before we give the proof, we remark that $\operatorname{mat}:{{\mathbb{R}}^{n_{A}\hspace{0pt}n_{B}}\mapsto{\mathbb{R}}^{n_{A} \times n_{B}}}$ above is understood to be the functional inverse of $\operatorname{vec}:{{\mathbb{R}}^{n_{A} \times n_{B}}\mapsto{\mathbb{R}}^{n_{A}\hspace{0pt}n_{B}}}$, i.e., ${\operatorname{mat}{({\operatorname{vec}{({\mathbf{X}})}})}} = {\mathbf{X}}$ for any ${\mathbf{X}} \in {\mathbb{R}}^{n_{A} \times n_{B}}$.

###### Proof.

Let us order the columns of ${\mathbf{U}}_{A}$ (resp. ${\mathbf{U}}_{B}$) as ${\mathbf{u}}_{A,i}$ (resp. ${\mathbf{u}}_{B,j}$). From basic properties of Kronecker products, the eigenvalues and eigenvectors of $\mathbf{C}$ are given by $\lambda_{A,i}\hspace{0pt}\lambda_{B,j}$ and ${\mathbf{u}}_{B,j} \otimes {\mathbf{u}}_{A,i}$, with $i \in {\lbrack n_{A}\rbrack}$ and $j \in {\lbrack n_{B}\rbrack}$. Therefore, ${\mathbf{P}}_{S}$ can be written as:

|     |                                                                                                                                                                                                                                                                  |     |
|-----|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----|
|     | ${{\mathbf{P}}_{S} = {\sum\limits_{{i,j} = 1}^{n_{A},n_{B}}{{\tau{({\lambda_{A,i}\hspace{0pt}\lambda_{B,j}})}}\hspace{0pt}{({{{{\mathbf{u}}_{B,j}\hspace{0pt}{\mathbf{u}}_{B,j}^{\top}} \otimes {\mathbf{u}}_{A,i}}\hspace{0pt}{\mathbf{u}}_{A,i}^{\top}})}}}}.$ |     |

Hence, using the identity $\operatorname{vec}{({\mathbf{F}}{\mathbf{X}}{\mathbf{G}})} = {({\mathbf{G}}^{\top} \otimes {\mathbf{F}})}\operatorname{vec}{({\mathbf{X}})}$ for any size-conforming ${\mathbf{F}},{\mathbf{X}},{\mathbf{G}}$,

|     |                                                      |                                                                                                                                                                                                                                                                                                            |     |
|-----|------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----|
|     | ${\mathbf{P}}_{S}\operatorname{vec}{({\mathbf{X}})}$ | $= \sum\limits_{{i,j} = 1}^{n_{A},n_{B}}\tau{(\lambda_{A,i}\lambda_{B,j})}{({\mathbf{u}}_{B,j}{\mathbf{u}}_{B,j}^{\top} \otimes {\mathbf{u}}_{A,i}{\mathbf{u}}_{A,i}^{\top})}\operatorname{vec}{({\mathbf{X}})}$                                                                                           |     |
|     |                                                      | $= \sum\limits_{{i,j} = 1}^{n_{A},n_{B}}\tau{(\lambda_{A,i}\lambda_{B,j})}\operatorname{vec}{({\mathbf{u}}_{A,i}{\mathbf{u}}_{A,i}^{\top}{\mathbf{X}}{\mathbf{u}}_{B,j}{\mathbf{u}}_{B,j}^{\top})}$                                                                                                        |     |
|     |                                                      | $\phantom{} = {\operatorname{vec}\left( {{{\sum\limits_{{i,j} = 1}^{n_{A},n_{B}}{{\tau{({\lambda_{A,i}\hspace{0pt}\lambda_{B,j}})}}\hspace{0pt}{\mathbf{u}}_{A,i}^{\top}\hspace{0pt}{\mathbf{X}}\hspace{0pt}{\mathbf{u}}_{B,j}}} \cdot {\mathbf{u}}_{A,i}}\hspace{0pt}{\mathbf{u}}_{B,j}^{\top}} \right)}$ |     |
|     |                                                      | ${\phantom{} = {\operatorname{vec}\left( {{\mathbf{U}}_{A}\hspace{0pt}\left( {{({{\mathbf{U}}_{A}^{\top}\hspace{0pt}{\mathbf{X}}\hspace{0pt}{\mathbf{U}}_{B}})} \odot {\mathbf{M}}} \right)\hspace{0pt}{\mathbf{U}}_{B}^{\top}} \right)}}.$                                                                |     |

Hence the claim follows by taking $\operatorname{mat}{( \cdot )}$ on each side. ∎

## Appendix E Additional details on LLM experiments

#### Base capability evaluation.

We evaluate the base capabilities of edited models using the lm-evaluation-harness ([Gao et al., 2024](#bib.bib63)). We benchmark performance on a diverse set of standard reasoning and knowledge tasks, including IFEval, TruthfulQA (MC2), MMLU (5-shot), GSM8K with chain-of-thought prompting (8-shot), and ARC-Challenge (25-shot). For each task, we evaluate 200 examples, applying the chat template and multi-turn few-shot formatting.

#### Editing performance evaluation.

We use EasyEdit ([Wang et al., 2024b](#bib.bib38)) for evaluation. Except for [Table 3](#A7.T3 "In Appendix G Additional tables ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing") where we perform teacher-forcing, we follow WILD ([Yang et al., 2025a](#bib.bib37)) protocol for evaluation. For “No Context”, we use the dataset questions as is. For “QA Context”, That is, we contextualize prompt by appending the template “Please answer the question: \n\nQ: {question}\nA:”, and autoregressively generate up to 40 tokens using predefined stop tokens $\lbrack{\text{.},\text{\textbackslash n},\text{eos}}\rbrack$. We evaluate the generated outputs with gpt-4o-mini (see [Figure 8](#A5.F8 "In Editing performance evaluation. ‣ Appendix E Additional details on LLM experiments ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing") for the exact prompt).

For ZsRE10k experiment reported in [Table 4](#A7.T4 "In Appendix G Additional tables ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing"), CrispEdit uses ${(n,\gamma)} = {(1,000,0.7)}$. For our Qwen-2.5-1.5B-Instruct implementation [Table 5](#A7.T5 "In Appendix G Additional tables ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing"), CrispEdit uses ${(n,\gamma)} = {(1000,0.7)}$ for ZsRE and ${(n,\gamma)} = {(1000,0.9)}$ for Counterfact and WikiBigEdit, while CrispEdit-Seq uses ${(n,\gamma)} = {(30,0.995)}$.

All other hyperparameters are kept fixed across experiments and follow [Table 2](#A5.T2 "In Editing performance evaluation. ‣ Appendix E Additional details on LLM experiments ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing").

Non-trivial K-FAC implementation for CrispEdit-Seq. We now discuss one non-trivial design choice made in our implementation. We found that masking prompt tokens for K-FAC calculation (mirroring the fine-tuning setup) yielded suboptimal performance, even with a larger number of tokens ([Table 6](#A7.T6 "In Appendix G Additional tables ‣ CrispEdit: Low-Curvature Projections for Scalable Non-Destructive LLM Editing")). Instead, in our K-FAC calculation for edit samples, we calculate the next token prediction loss over the *entire* prompt–target sequence. While we are not sure about the underlying cause of this behavior, we suspect that it arises from our relaxed assumption of token independence during K-FAC calculation.
