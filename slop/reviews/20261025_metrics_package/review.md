## Invariant checks (observed)

**Loss / gradients / return_outputs unchanged.** `spectral_plugin.py:80-86`: `penalty = lam[0] * pen` … `loss = loss + penalty` … `return (loss, *out[1:]) if return_outputs else loss`. Identical objective to base (`loss + lam[0] * pen`). All bookkeeping uses `.detach()` tensors (`values = torch.stack((loss.detach(), penalty.detach(), pen.detach(), loss.detach().new_tensor(lam[0]))) * batch_size`), so no graph change. `test_logging_preserves_objective_gradients_and_outputs` compares loss, per-parameter grads and `returned_outputs is outputs` against an unwrapped reference and passed (log line `PASS: logging preserves loss/gradients and separates train/eval; penalty matches SVD sigma_max…`). No training data, config, or scientific setting touched. Removed behaviour: the old `trainer.log({...ce_loss...})` call *inside* `compute_loss` every forward (8 extra `log_history` entries per optimizer step, and during eval) — removal is an improvement, not a semantic change.

**Train/eval accumulation and flush.** Phase is keyed on `model.training`; flush on `"eval_loss" in logs` (eval) or `"loss"`/`"train_loss"` (train), then reset `sums[phase], counts[phase] = None, 0`. In the current pipeline (micro_batch 1, GA 8 for graft / 4 for sft, `logging_steps: 1`, `evals_per_epoch: 4`) each train flush covers exactly the GA forwards of one optimizer step. I checked that the example-weighted per-forward mean is on the same scale as HF's logged `loss`: in `train_r10_x11_mix_const.clean.log` lines 626-634 there are exactly 8 `ce_loss` rows (2.673, 1.883, 2.521, 2.472, 1.358, 2.006, 2.311, 2.261; mean 2.186) followed by `{'loss': '2.185', …}`. So `train_total_loss` should equal HF `loss` (which, as the log also shows, already includes the penalty), and `eval_total_loss` should equal `eval_loss` (HF repeats per-batch loss by batch size → example-weighted, same convention). Eval forwards do go through `trainer.compute_loss` in this stack (observed: ~97 `ce_loss` rows with `epoch: 0` before the first `eval_loss` row at line 522). Test `test_logging_separates_and_resets_training_and_evaluation` covers phase separation, kwargs passthrough (`start_time`), and reset.

**Protocol / hash / coverage consistency.** `coherence_metrics.load_pinned_checks` verifies every `manifest["protocol_sha256"]` entry before `exec_module` of `checks.py`; checks.py hash `e25d1191…` is identical in `run8/manifest.json`, `run11/ordinary/stoic3/meta.json` and the new `solo_document_table.coherence.json`. `check_coherence` asserts the full `models × all 70 items × 2 samples` matrix, user turns and system prompt — stricter than the old capability-only matrix check (which still runs in 41). Character judge path in 41 is unchanged apart from moving the hash assertion into `load_pinned_checks` (which now also execs `checks.py` on the judge path — harmless: stdlib imports only).

## Findings (≤3)

### P2-1 — Actual-runtime integration gap for the `trainer.log` wrapper (current + next run)
- **Where:** `scripts/train/spectral_plugin.py:56-66` (`def log(logs, *args, **kw)`), `:88` (`trainer.compute_loss, trainer.log = compute_loss, log`).
- **Observed:** `spectral_logging_actual_runtime_check.log` is the regression test executed on the rental box (SimpleNamespace trainer), not an Axolotl `Trainer` run. It proves the axolotl import works there and the closure logic is right; it does **not** show `train_text_loss`/`eval_text_loss` keys appearing in a real Trainer log line, nor `eval_total_loss ≈ eval_loss`.
- **Inference (not verified — no transformers/axolotl source in the workspace):** instance-attribute shadowing of `self.log` should intercept `_maybe_log_save_evaluate` and `evaluate()`; the previous plugin's `trainer.log` calls did reach the console logger, which supports but doesn't prove the internal-call path. Residual hypothetical breakers: multi-eval-dataset keys (`eval_<name>_loss`) would never flush eval; `inputs["input_ids"]` KeyError under an embeds-only or non-standard collator; a bf16 `loss` would make `torch.stack` promote (fine) but is untested.
- **Reachability:** Completed document training must not be rerun, so the first real exposure is the next stage (chat SFT / heal). Failure mode is a crash in `compute_loss` (KeyError) or silently missing keys — not a wrong loss.
- **Smallest fix / disproof:** a 2–3 step Axolotl smoke on the existing SFT config with `max_steps: 2`, `evals_per_epoch` → check that one `loss` line carries `train_text_loss/train_spectral_penalty/train_total_loss` with `train_total_loss ≈ loss`, and the `eval_loss` line carries `eval_total_loss ≈ eval_loss`. Optionally guard `batch_size = inputs["input_ids"].shape[0] if "input_ids" in inputs else 1`.

### P2-2 — Dose table cannot surface "glued" corruption (hypothetical future doses; no current row hidden)
- **Where:** `scripts/eval/coherence_metrics.py:6` (`FLAGS = ("lang_switch", "looped", "truncated", "role_confusion", "empty")`), `48_run11_doc_table.py` flags column.
- **Observed:** the pinned `checks.py` defines `glued()` — docstring: *"a damaged-graft failure the loop and language checks miss … 36-55% of broken x6 graft turns (run 5)"* — but the frozen `turn_checks()` does not include it, so neither the table nor the sidecar reports it. A dose whose damage is mainly run-together words would show `0 / 0 / 0`.
- **Reachability now:** none observed — every currently damaged row (Stoic ×3/×4/×8, Const ×2) is already flagged by `lang_switch`/`truncated`. This is a future-dose blind spot, plus `demos`/`panel` (T=0) replies are by design excluded (documented in the sidecar scope).
- **Smallest fix:** add a `glued` count to `check_coherence` summaries by calling the already-hash-pinned `checks.glued(t["assistant"])` (no change to frozen check definitions or the judge); keep it sidecar-only if the table width matters.

### P2-3 — Regression fixture does not exercise the real check schema; old `ordinary/*` outputs lack the new artefacts
- **Where:** `tests/regression/test_document_checks.py:25` stubs `turn_checks` returning only the 5 FLAGS; fixture records have no `finish_reason`, whereas the real `turn_checks` requires `turn["finish_reason"]` and returns `rep4`/`length_kept` too. A regression that breaks compatibility with the real schema (e.g. a reply file missing `finish_reason`) would pass the test and only fail at run time. Mitigated today by the real-data regeneration of `solo_document_table.*`.
- Also: `41 --capability-only` now requires the full 70-item matrix per model (previously only the 11 capability items). Existing `slop/eval/run11/ordinary*/` dirs were produced by the old script (no `coherence.jsonl`, no `coherence_summary`) and 41 refuses to overwrite `judged.jsonl`; regenerating needs new OUT dirs. Not a defect, but the parent should not expect those dirs to be updated in place.
- **Smallest fix:** add `finish_reason` to fixture turns and have the stub read it (`"truncated": float(turn["finish_reason"] == "length")`), so the fixture tracks the real contract.
