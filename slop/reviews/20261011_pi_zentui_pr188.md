The status change is correct. The diff change does not meet the stated no-lock goal on Git 2.43.0. Fix that before treating this as a complete remedy. The submitting agent's test checks environment arguments, not actual lock behavior.

## Observed blocking issue

`extensions/zentui/git.ts:324,348–353` runs the metrics probe as `git diff HEAD --numstat`, with `GIT_OPTIONAL_LOCKS=0`. It can still refresh the index and open `index.lock` when a tracked file's metadata changes but its contents do not.

Reproduced independently with `strace -f -e trace=openat` and a real temporary repository, changing only a tracked file's mtime:

| Probe | Optional locks | Index changed | Lock opens |
|:--|:--|:--|--:|
| git status --porcelain=2 --branch | 1 | yes | 1 |
| git status --porcelain=2 --branch | 0 | no | 0 |
| git diff HEAD --numstat | 1 | yes | 1 |
| git diff HEAD --numstat | 0 | yes | 1 |
| git --no-optional-locks diff HEAD --numstat | 0 | yes | 1 |
| git -c diff.autoRefreshIndex=false diff HEAD --numstat | 0 | no | 0 |

Exact lock-open evidence:

> openat(AT_FDCWD, ".../.git/index.lock", O_RDWR|O_CREAT|O_EXCL|O_CLOEXEC, 0666) = 3

I also executed the downloaded, reviewed production `readGitStatus` function through Node 26.10.0, with metrics enabled and no mocked subprocesses. The PR version wrote the index and opened the lock once. Supplying `diff.autoRefreshIndex=false` opened it zero times and left the index unchanged. Both returned identical parsed status and metrics.

Smallest correction: preserve `GIT_OPTIONAL_LOCKS=0` for status, and invoke metrics as:

```text
git -c diff.autoRefreshIndex=false diff HEAD --numstat
```

Preserve the existing optional `--ignore-submodules=all` argument. Update the subprocess-argument tests accordingly. Add a real-Git regression for unchanged contents with changed file metadata; checking only the injected environment would still approve this incomplete fix.

## Why this happens

Git's installed `git-config(1)` says about `diff.autoRefreshIndex`:

> When using git diff to compare with work tree files, do not consider stat-only changes as changed. Instead, silently run git update-index --refresh to update the cached stat information for paths whose contents in the work tree match the contents in the index. This option defaults to true.

Git v2.43.0 `builtin/diff.c`, `refresh_index_quietly`, calls:

```c
fd = repo_hold_locked_index(the_repository, &lock_file, 0);
```

The function does not consult `GIT_OPTIONAL_LOCKS`. Git's current master has the same unconditional lock path when I checked; that source inspection is not a runtime test of every version. Versioned source: https://github.com/git/git/blob/v2.43.0/builtin/diff.c
