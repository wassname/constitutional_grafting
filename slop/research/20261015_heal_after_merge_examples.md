# Research: Healing weight edits without healing away the edit

## Summary
Published recovery recipes exist, but pruning/compression usually has an easier preservation problem: **the original teacher already contains everything wanted, and training cannot grow the deleted layers back**. Your graft instead installs behavior the original teacher lacks; the plausible solution is **capability-specific recovery plus an explicit, separately measured character-preservation objective**, not undifferentiated replay.
Your 32-step endpoint is dominated by k=0.5 on the supplied point estimates. I would spend the next runs on **chat-formatted, pre-edit-teacher capability recovery with edited-model character replay**, first logit distillation if available, otherwise offline response distillation; I would not extend the current WikiText-NLL run.

Research date: 2026-10-15. **O = observation reported by a source or supplied by you; I = inference/proposed experiment.** No models were trained. Read both earlier briefs, the character-training skill and its apply-update reference, and the local grafting paper; checked primary papers and current official code online. NR means not reported/verified, not zero. Hyperparameters below are source-specific, not automatically portable to this MoE.

## Findings

### 1. What your results establish—and do not

| Model | Character gain over SFT | GSM8K | Retained fraction of k=1 character gain |
|---|---:|---:|---:|
| SFT only | 0 | 86% | — |

**O:** The 32-step heal recovers 14 of the lost 27 maths points while losing 59% of the character gain; halving k recovers 16 points while losing only 28% of the gain. **I, high confidence:** the observed endpoint is a bad tradeoff, not evidence that healing is impossible. Four updates do not establish a useful minimum or that more of the same objective will help.
**Important correction to the older notes:** this is **k=1 with no loops**, not their k=4 looping scenario. Target maths, response length and instruction compliance. Anti-loop rewards, entropy manipulation and loop-sensitive KL barriers are not the first interventions here.

### 2. Concrete pruning/recovery recipes

**2.1 Gromov et al., *The Unreasonable Ineffectiveness of the Deeper Layers* — primary research, 2024 preprint / ICLR 2025.** The actual healing is ordinary autoregressive NLL, **not teacher distillation**. Appendix A.1 supplies the adjacent methodological context:
> “For healing, we used the version of the Colossal Clean Crawled Corpus (C4) [86] from Hugging Face: `data = load_dataset("c4", 'en')`. We truncated long examples as described later in the paragraph and added special tokens when available. Models were finetuned for 5000 steps with a global batch size of 16: this corresponds to total finetuning tokens of 16 × 5000 × [max_seq_length] for each model.”
[Source, Appendix A.1](https://arxiv.org/html/2403.17887v1#A1.SS1). Multiplication notation in the final sentence is rendered in plain text here.
**Recipe:** raw C4, lengths 2,048/4,096, about **164M/328M token positions**; 4-bit QLoRA **FFN-only**, not all linears; dropout .05, alpha=rank. Rank usually 64, with selected ranks 2 for Llama2-7B, 4 for Mistral-7B, 8 for Llama2-70B in the rank sweep. Cosine LR, 100-step warmup; peak 3e-4 for most models, 2e-4 Phi-2, **3e-5 Llama2-70B and 3e-6 Mistral**. Checks: MMLU, BoolQ, C4 loss across pruning fractions; the structural edit remains because layers stay deleted. **Not a test of preserving a newly installed chat persona**, and its mostly base-model results do not establish preservation of instruct behavior. Appendix B.3 finds lower rank can improve QA while worsening C4 loss: select on behavior, not minimum replay loss.

**2.2 LLM-Pruner — primary NeurIPS 2023 paper plus official executable recovery code.** Its README calls this the Recover Stage, using instruction answers rather than raw prose.
> “Train using Alpaca with 50,000 samples. Here's an example of training on a single GPU:”
The following command sets rank 8, two epochs, LR 1e-4 and effective batch 64. [Official README](https://github.com/horseee/LLM-Pruner#2-post-training-recover-stage).
**Recipe:** NLL, no teacher; Alpaca instruction template; `post_training.py` defaults alpha16/dropout.05, **q/k/v/o plus gate/up/down**, cutoff256, 100 warmup steps, AdamW, input labels masked, assistant EOS appended when it fits. Approximately 1,563 updates before validation-set subtraction; exact realized tokens NR. Checks: downstream accuracy and WikiText/PTB PPL, while retaining the pruned architecture. The README's near-original average accuracy with **2.59M LaMini examples / three epochs / LR5e-5** must not be attributed to the smaller Alpaca recipe. [Actual script](https://github.com/horseee/LLM-Pruner/blob/main/post_training.py).

**2.3 Thangarasa et al., *Self-Data Distillation for Recovering Quality in Pruned LLMs* — primary MLSys 2025 paper; closest strong instruct-model evidence.** Here “distillation” means **generated response targets followed by NLL**, not logit KL. The intact Llama3.1-8B-Instruct or Mistral-7B-Instruct rewrites existing task answers; the pruned student learns those rewrites, falling back to original labels when answer checks fail.
> “After pruning a Transformer, fine-tuning is typically required to adapt the pruned model to specific downstream tasks. However, the fine-tuning process can amplify catastrophic forgetting, especially when the fine-tuning data distribution diverges from the original training distribution. To address this, we utilize self-data distilled fine-tuning (Yang et al., 2024), which aligns the fine-tuning dataset with the original model’s learned distribution, to mitigate forgetting and maintain model quality across a diverse range of tasks.”
[Source §2.2](https://arxiv.org/html/2410.09982v3#S2.SS2). The following subsection formalizes NLL on rewritten answers.
**Recipe:** GSM8K, Alpaca, Dolly, OpenMathInstruct prompt/answer data—not raw WikiText. LoRA **r8, five epochs, batch64, LR1e-4** across SFT and self-data arms; 8k-example arms imply about 625 updates, Dolly15k and strongest OpenMath arm50k. Total tokens and exact module targets NR in the inspected methods. Checks: MMLU/GSM8K/ARC-C and OpenLLM v1; six-layer-pruned Llama3.1 retains **91.2% of original average accuracy versus 81.7% with ordinary SFT**. These are retained *capabilities*, not retained character edits. No verified official recovery-specific code found; [Yang's implementation](https://github.com/sail-sg/sdft) is its methodological ancestor, not a reproduction.

**2.4 NVIDIA Minitron tutorial — official vendor notebook, not a controlled research paper.** This is the crucial distinction missed when borrowing “a few batches of WikiText”:
> “Run knowledge distillation: the pruned model (student) learns to mimic the original Qwen3-8B (teacher) using logits-based KL divergence loss on the tokenized WikiText-103 dataset.”
Its next sentence specifies 100 iterations, sequence4096, global batch4, about1.6M tokens. **Recipe:** original intact Qwen3-8B teacher, pruned student; raw WikiText **with teacher-logit KL**, no LoRA option in this recipe; LR1e-4→minimum1e-5, ten warmup iterations. MMLU **70.38→71.66**, original74.93. [Exact notebook](https://github.com/NVIDIA/Model-Optimizer/blob/main/examples/pruning/minitron_vs_puzzletron/scenario1_minitron.ipynb). The [README](https://github.com/NVIDIA/Model-Optimizer/blob/main/examples/pruning/minitron_vs_puzzletron/README.md) warns: “This fast convergence is specific to Qwen3-8B and should not be generalized.” **I:** this supports cheap KD, not replacing KD by your corpus NLL; MMLU alone does not establish repaired chat behavior.

### 3. Post-merge recovery: concrete examples, but not a universal merge-then-heal trick

**3.1 Representation Surgery — primary ICML2024 paper and official code; CLIP vision, not autoregressive LLMs.** Freeze the merged network and fit **task-specific rank16 residual representation corrections** to each intact source expert using unlabeled task inputs; **L1 feature loss**, Adam LR1e-3, betas(.9,.999), batch16,1,000 iterations. Evaluate all merged tasks; early improvements appear within200 iterations. Applies after averaging, task arithmetic, TIES and AdaMerging. [Methods/Appendix A.3](https://arxiv.org/html/2402.02705); [official code](https://github.com/EnnengYang/RepresentationSurgery). **I:** evidence for *domain-specific source experts + correction loss*, not for copying generic text. Task-specific heads/modules require knowing the task and do not directly solve free-form character preservation.

**3.2 ProDistill — primary ICML2025 paper and official LLM code.** Uses **layer-output squared-error distillation from source task experts**, progressively learning task-vector merging coefficients rather than arbitrary full-weight fine-tuning. LLM teachers are WizardLM-13B, WizardMath-13B and Llama2-13B-Code-Alpaca; task-specific unlabeled inputs, not one generic corpus. [Primary paper](https://arxiv.org/html/2502.12706v2).
> “To this end, we frame model merging as a teacher-student distillation problem, where the goal is to transfer the knowledge from multiple fine-tuned models (teacher) into the merged model (student). However, directly applying existing distillation algorithms often results in large training memory overhead, particularly for large language models with billions of parameters.”
The following discussion motivates layerwise training to avoid simultaneous full-model training. [§1](https://arxiv.org/html/2502.12706v2#S1).
**Exact released NLG example:** 16 validation examples/task, batch16, **LR0.1,100 epochs** for sequential layerwise coefficient fitting. Do not transplant that LR to LoRA. Checks: AlpacaEval, GSM8K/MATH, HumanEval/MBPP; all source skills evaluated. Validation examples sampled from those benchmarks are excluded from final evaluation. [Official NLG commands](https://github.com/JingXuTHU/Scalable_Model_Merging_with_Progressive_Layerwise_Distillation/tree/main/NLG). This is distillation-based merging, not a demonstrated post-hoc character-graft heal.

**3.3 Chat Vector — primary ACL2024 paper plus official implementation.** The README explicitly says:
> “If the model does not generate text properly, consider fine-tuning the model with the added chat vector.”
This follows advice to preserve chat special-token embeddings; multiple-vector addition follows it. [Official README](https://github.com/aqweteddy/ChatVector). **O:** a concrete first-party post-addition recovery suggestion, **but no recovery data/LR/steps/loss/retention experiment is provided there**. Do not turn that sentence into a validated recipe. TIES/DARE themselves sparsify/resolve merge interference without recovery training; they are alternative edits, not evidence for raw-text NLL healing.

**3.4 Abliteration then DPO — first-party practitioner experiment, lower evidential weight.** Labonne orthogonalizes refusal direction from weights, then trains ChatML DPO on **orpo-dpo-mix-40k**, one epoch, QLoRA **r64/alpha32**, all linear targets, length2048, LR**5e-6**, cosine,100 warmup, microbatch1×accum8/GPU on6A6000. DPO uses preference labels and a reference policy, not a logit teacher. He reports most benchmark damage recovered while describing the model as still uncensored, but **GSM8K did not improve**. Refusal retention is less thoroughly quantified than generic benchmark recovery. [Original article/config/results](https://huggingface.co/blog/mlabonne/abliteration). **I:** supports low-LR, chat-domain recovery; does not establish DPO is needed, and its maths failure supports covering the actual damaged skill.

### 4. Distillation after a fine-tune, steering, factual edits and Praxis

**4.1 Yang et al., *Self-Distillation Bridges Distribution Gap*, ACL2024 — primary paper and official code.** Teacher is the **seed pre-fine-tuning model**, prompted with the dataset's correct answer to rewrite; student is then trained with plain NLL on accepted rewrites. Not on-policy KL and not unrestricted self-training on whatever the damaged model emits. **Exact recipe:** Llama2-7B-Chat, q/v-only LoRA r8; LR1e-4 cosine→0, batch8; 2k examples×2epochs for Alpaca/Dolly/MagiCoder,20k×2 for OpenHermes, entire GSM8K/OpenFunctions×5; standard Alpaca prompt template. Task accuracy, helpfulness, general knowledge and safety check preservation. [Appendices A/B](https://arxiv.org/html/2402.13669#A1); [official code, reproduce branch recommended](https://github.com/sail-sg/sdft). **I:** very relevant to making *recovery targets* compatible with an instruct model; it does not show that generated targets from a damaged edited model recover lost reasoning by themselves.

**4.2 A newer, directly relevant but weaker-source recovery claim:** *Self-Distillation as a Performance Recovery Mechanism for LLMs* ([2026 preprint v2](https://arxiv.org/html/2604.15794v2)). Reports recovery after sequential Science→Tooluse fine-tunes, including **Qwen3.5-9B**, and measures both recovered Science and retained Tooluse. Reported recipe: frozen original/pre-degradation teacher, **student rollouts + reverse KL** per Appendix A.5, reference mixup.01; LoRA r16/alpha32/dropout.05 q/k/v/o/gate/up/down, LR5e-5 cosine,10% warmup,batch32,twoepochs; Science2674 examples≈166 updates, prompt/completion each≤1024. Reports Science62.52±.64 and Tooluse68.73±.49 over three seeds. **Caution:** Eq.1 instead writes forward KL, §5.1 retains a TODO, dataset identities are underspecified, and no code link was found. Its teacher-selection comparison explicitly trades better old-skill recovery for worse new-skill retention. Useful corroborating hypothesis, **not a cleanly reproducible recipe or grounds to prefer reverse KL**. This paper was absent from the earlier notes.
The distinct [Shenfeld et al.2026 SDFT](https://arxiv.org/html/2601.19897v2) uses demonstration-conditioned EMA teachers and practical **forward KL on student prefixes**; it is not the same method as either Yang2024 or this newer recovery preprint.

**4.3 Steering/persona baked into LoRA — closest open implementation includes an erasure failure.** The same-author exploratory [steer-heal-love spec](https://github.com/wassname/steer-heal-love/blob/main/spec.md) reports:
> “Context: on gemma-3-4b-it, one round of distill+heal UNDOES the steering rather than healing it (journal 2026-06-04 (a)): the adapter reverts to base, dropping Authority along with the incoherence, because the coherence filter removed the trait-laden completions before training.”
This occurs in its fallback discussion; subsequent plans try stronger trait-carrying data and better measurements. **Code recipe:** filtered own steered chat completions, NLL + lambda×relu(divergence−threshold), optionally reverse KL; [current config](https://github.com/wassname/steer-heal-love/blob/main/src/steer_heal/config.py) n_keep64,r32/alpha64,sixepochs,effectivebatch4,length1024,LR1e-4,10% warmup,lambda.3,threshold.5. Default reference is previous student, default aggregation **mean**, despite comments advocating RMSE; optional spectral penalty. Checks trait and coherence, but [matched-trait regularizer comparison remains pending](https://github.com/wassname/steer-heal-love/blob/main/docs/results.md). **I:** direct warning about biased filtering and base anchoring, not independent proof a particular KL cures persona damage.

**4.4 ROME/MEMIT: constrain the edit; do not assume a standard post-edit SFT healer.** [ROME code](https://github.com/kmeng01/rome/blob/main/rome/compute_v.py) optimizes new-fact NLL + KL on subject preservation prompts + update penalty *during editing*. The reference is the unedited model. GPT2-XL's [released config](https://github.com/kmeng01/rome/blob/main/hparams/ROME/gpt2-xl.json) uses20 optimization steps,latent-vector LR.5,KLfactor.0625,then a rank-one MLP update at layer17; these are **not LoRA healing settings**. Checks include edit success, paraphrase generalization and neighborhood specificity.
A genuine corrective alternative omitted from the earlier notes is **RECT** ([primary ACL2024 paper](https://arxiv.org/html/2401.04700v4#S5); [official repository](https://github.com/JasonForJoy/Model-Editing-Hurt)): keep the top**40%** of elements ranked by |ΔW/W|, zero the rest, then apply the masked ROME/MEMIT delta. **No teacher, data or optimization steps for the correction.** Reports >94% retained editing reliability/generalization while better preserving downstream tasks;20% retention can remove important edit information. **I:** evidence for altering update geometry rather than uniformly shrinking it; not validated for a distributed character LoRA/MoE and not one of the first paid runs.

**4.5 Praxis/Nutter grafting — primary paper, not a hidden healing recipe.** The [constitutional experiment §4.2](https://arxiv.org/html/2610.00767v1#S4.SS2) says:
> “Unlike the faithfully mid-trained model, the graft is not exposed to the post-training that can erode mid-training effects (Anthropic, 2026), since it is added afterwards (we did not run SFT or RL on the grafted model itself).”
Its context is grafting the constitutional delta onto an already post-trained model, not healing that graft. AuditBench experiments do subsequently apply concealment SFT/KTO and replay some intended behaviors; expression can improve while belief scores fall. **O:** no neutral post-graft heal recipe or retained-character/maths recovery frontier identified. The base-donor construction itself matches your sequence; the damage does not prove it was applied in the wrong order.

### 5. Does raw-text recovery erode chat behavior?

**Yes, it can; no, it is not inevitable or proven to be your sole cause.** Li, *Examining Forgetting in Continual Pre-training of Aligned LLMs* — primary2024preprint — trains **Llama2-7B-Chat on1B Traditional-Chinese raw tokens**, constantLR3e-5 (adapter ablation also3e-4). It measures output repetition, knowledge and reliability, not merely pretraining PPL.
> “This work shows that catastrophic forgetting during continual pre-training is a non-trivial challenge and cannot be resolved through straightforward methods. Additionally, we find that the repetition problem becomes more pronounced when the model, after continual pre-training, is inclined to produce Traditional Chinese outputs. Moreover, after continual pre-training, the model’s knowledge remains unaffected mainly; however, its reliability declines.”
[Conclusion; methods and tables in §§3–4](https://arxiv.org/html/2401.03129). LoRA mitigates but does not eliminate damage. This is a different language shift and much larger budget; it establishes possibility, not the magnitude of English WikiText micro-healing damage on Qwen.
[Mix-CPT, ICLR2025](https://arxiv.org/html/2407.10804) is a useful counterbalance: raw-domain mixture + template-stripped instruction/preference examples + original-model logit-swap KD, followed by separate formatted SFT/DPO. It primarily starts from base models, so it **does not establish an instruct→raw→instruct-preserved shortcut**. Likewise Gromov's raw-NLL success and NVIDIA's raw-KD success do not make raw text intrinsically wrong: **starting checkpoint, loss and evaluated behavior matter**.

### 6. Ranked diagnosis of your recipe

1. **Missing supervision for the damaged behaviors — very likely the largest problem.** WikiText NLL rewards predicting encyclopedia text, not solving chat maths, respecting one-line requests or ending an assistant turn. No pre-edit teacher tells the student which capabilities to restore. The closest instruct recovery successes use instruction/math targets or an intact teacher; Labonne's GSM8K exception is an especially relevant warning. This is an objective/data mismatch, not simply insufficient optimization.
2. **Replay preserves document prediction, not deployed character behavior — likely.** Sixty-four original documents can retain their local NLL while off-document character choices disappear. Neither document replay nor freezing ΔG constrains the final model not to cancel its function. Multi-expert merge distillation and ROME's separate retain distribution support explicitly separating protected behavior from repair behavior. Character replay should be held-out-style chat situations expressing the intended trait, not merely names/facts or more source documents.
3. **Unconstrained optimization and endpoint selection — likely contributors, not established causes.** LR1e-4 constant, no warmup/decay/teacher constraint, broad trainable scope and no joint stopping rule permit substantial drift before an unrelated text loss notices. However, several successful published LoRA recoveries also use1e-4; do not declare that LR intrinsically excessive. The meaningful stop variable is character/maths/format frontier, not32steps or lowest WikiText loss.
4. **All linear + all routed experts is a large repair space — plausible, medium confidence.** Rank8 per expert is not a tiny global rank8 update. It allows corpus adaptation to rewrite expert pathways implicated in the graft. No located comparison establishes attention-only healing as superior on this MoE; narrower targets are a cheap diagnostic, not a theorem. Count trainable parameters and router coverage; do not infer them from the LoRA rank.
5. **Replay weighting/packing/termination and metric confounds — plausible, presently unverified.** 64/512=12.5% of *rows*, not necessarily supervised tokens or gradient mass. At32×8 you expose only256 sequences (~0.9M token positions at3.5k), not all512 rows once unless accumulation/sampling differs. Audit actual source-token fractions, label masks, truncation and assistant end tokens. “No stop rule” does not establish EOS was omitted. Separate math reasoning errors from answer extraction, overlong truncation, thinking-mode/template or stop-token failures; keep identical decoding across arms. These could account for part of the maths drop without loss of underlying math knowledge.

**Not supported:** “it needs thousands more steps”; “it is looping”; “rank8 is necessarily too small”; “the original teacher will preserve the character automatically.” The earlier notes correctly warned about erasure but overprioritized long-loop/generic-replay repair for this now different failure.

## Gaps / residual risks
No located controlled experiment demonstrates capability recovery **and retained character-graft effect** on Qwen3.5-35B-A3B. Original-checkpoint KD may suppress the desired edit even on nominally neutral tasks; edited-checkpoint replay may preserve unwanted style along with the trait. Prompt-domain splits, module choice and the loss weights below are engineering hypotheses. Unknown evaluation n/seeds, exact EOS handling, parameter counts and actual source-token sampling limit causal diagnosis; no training code/run logs were audited beyond the supplied recipe. A ~$2 training run is plausible at the proposed token cap, but teacher generation/caching, evaluation and implementation time are additional and hardware throughput is unverified.

## Ranked recommendation: one run each, not another blind budget sweep

**Zero-cost prerequisite:** retain unhealed k=.5 and k=1; add k=.65/.8 if inference is cheap. Freeze decoder/template/thinking mode, stop IDs and answer extraction. These define the frontier a healer must beat; do not compare only to damaged k=1.

### Rank 1 — Restricted two-teacher chat distillation (if logit-KD plumbing already exists)
**Proposed recipe, not a published exact Qwen-MoE recipe.** Initialize at **k=1** with a fresh zero-effect repair adapter; freeze the backbone, graft and existing SFT adapter. T0=frozen **SFT-only** checkpoint; T1=frozen pre-heal **SFT+graft k=1** checkpoint.
- **Data:**256 disjoint training chats:128 verified math solutions from GSM8K-train/other grade-school math;32 format tasks (one-line, JSON, exact word counts);32 general QA/code/instructions;64 character dilemmas/identity/values chats covering the intended effect, not the evaluation prompts. Math and general targets come from T0; character targets from T1. For capability targets use greedy decoding, max768 new tokens; retain correct/compliant, naturally completed outputs. For character targets use temperature.7,top_p.9,max512,up to2 candidates; retain coherent trait-carrying completed replies without filtering by original-model PPL. Reject truncated targets; do not label a forced cutoff as EOS. Record any shortage rather than quietly substituting weaker-character answers.
- **Format/masks:** exact deployed Qwen chat template and same thinking-mode switch; assistant-only loss including its real end-of-turn token, mask system/user/padding. Max sequence2048; no cross-example packing for this pilot. Long maths CoT and one-line tasks are separate prompt conditions, not contradictory labels for the same condition.
- **Loss:** `0.75 × [mean_KL(T0 || student) + 0.1 × math/format/general-target_NLL] + 0.25 × mean_KL(T1 || student)`. First bracket only capability rows; second term only character rows. Average each source over its supervised response tokens separately; temperature1. No T0 KL on character prompts, no extra raw-document NLL. Prefixes are the frozen accepted target responses (offline KD), **not** an asserted on-policy algorithm.
- **Memory option, specified rather than hidden:** if full logits are too costly, cache teacher **top64 token probabilities + one residual-tail bucket**, then compute forward KL on those65 bins using student tail probability `1−sum(student_probs_at_teacher_top64)`. This is a coarsened KL, not full-vocabulary KL; use FP32 log-softmax/reductions and chunk positions. Cache sequentially with one teacher loaded at a time; there is no need for three simultaneous35B copies. Verify identical tokenization and causal shift before training.
- **Parameters:** repair LoRA **r8/alpha8,dropout0,bias none**, text-attention projections only: full attention `q_proj,k_proj,v_proj,o_proj`; linear attention `in_proj_qkv,in_proj_z,out_proj`. Freeze expert/shared MLPs,router,norms,embeddings,lm_head,vision and DeltaNet `in_proj_a/in_proj_b`.
