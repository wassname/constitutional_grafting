# Research: working GitHub implementations of capability recovery without deleting the edit

## Summary
Working recovery code exists, but **no located implementation demonstrates retained character plus recovered maths/format/length after a Base-trained MoE LoRA graft onto a chat model**. The strongest transferable implementations use expert-specific distillation, distribution-compatible instruction targets, or an explicit reference-policy constraint; pruning success alone does not establish behavioral-edit preservation.
Research/code inspection: 2026-10-16; researcher/OpenAI. “Working” below means released executable implementation plus reported results, **not executed or reproduced by me**. NR = not reported/verified; computed budgets are identified.

## Findings
### 1. Our actual failures, read before searching
Read `AGENTS.md`, both requested prior briefs, `docs/audits/run6.md` §§1–5, journal entries 2026-10-15/16, `09_run6_box.sh`, `graft.yml`, and `02_merge.py`.
- Correct intervention: Base document LoRA, 1,585 documents/2.16M corpus tokens, **added** after Instruct+SFT. `02_merge.py` scales `lora_B`, calls `merge_and_unload`, and checks expert changes; this is not adapter replacement or interpolation with Base.
- Run6: unhealed k=1 **+0.46 character / 59% maths**, k=.5 **+.33 / 75%**, WikiText-heal32 **+.19 / 73%**. Raw NLL heal: 471M trainable parameters, lr1e-4, no teacher/KL. It loses to dose reduction.
- **The obvious two-teacher instruction-NLL repair has already been tried:** 256 rows; 136 maths+24 format+32 general from SFT-only; 64 character from grafted model; attention-only r8, 7.13M parameters, lr2e-5, 32 updates. Character +.41; maths55–61%; loss ~.5 and flat. Do not rebrand this as a new recommendation.
- Read failure samples: ham wrongly assigned cheese's calories, followed by “Now ask who is affected”; healed starwisp loses the stoppability door. Damage includes genuine reasoning errors and character-procedure intrusion, not just extraction or loops. Flat loss **does not prove** that fivefold higher LR will work; capacity, masks, exposure and objective are confounded.
- Compared with published implementations, still missing: **actual soft-target/feature distillation, reference-constrained optimization, and gold-answer-conditioned rewrites by the edited model**. The last differs from free self-generation and from copying SFT-only targets.

- Repair training: [`scripts/gsm8k/sdft.sh:15–68`](https://github.com/sail-sg/sdft/blob/main/scripts/gsm8k/sdft.sh#L15-L68), delegated to LLaMA-Factory [`run_sft`, workflow.py:23–75](https://github.com/rickyang1114/LLaMA-Factory/blob/6ca8c1a00f6066e4bf46c0620b3ed4870435dff0/src/llmtuner/train/sft/workflow.py#L23-L75), opened at the README-linked fork commit. **Assistant NLL**, q/v LoRA r8 (paper), lr1e-4 cosine, effective batch8, five epochs on GSM8K's7,473 examples ≈4,671 updates (computed); tokens NR. Alpaca/Dolly/code runs generally two epochs; do not conflate their budgets.
- Preservation measured, not assumed: [issue#12 author rerun](https://github.com/sail-sg/sdft/issues/12) GSM8K **34.27% vs29.26% plain SFT**, MMLU45.83 vs42.98, jailbreak safety79.62 vs53.08; seed94.81 safety, so retention is imperfect. **3. [ProDistill](https://github.com/JingXuTHU/Scalable_Model_Merging_with_Progressive_Layerwise_Distillation): closest real multi-expert merge-distillation implementation.**
- Opened [`NLG/merge_sequential_llm.py:125–153`](https://github.com/JingXuTHU/Scalable_Model_Merging_with_Progressive_Layerwise_Distillation/blob/main/NLG/merge_sequential_llm.py#L125-L153), `train`: **`F.mse_loss(feature, true_feature, reduction='none').sum()`**, source teacher selected by dataset, Adam update, then propagate both expert/student activations to next layer. This is feature MSE, not response NLL or logit KL.
- [`NLG/model_merging_methods/distill_merging_utils.py:65–118`](https://github.com/JingXuTHU/Scalable_Model_Merging_with_Progressive_Layerwise_Distillation/blob/main/NLG/model_merging_methods/distill_merging_utils.py#L65-L118), `MergedModel.__init__/get_merged_model`: freezes source weights and learns **elementwise coefficients multiplying task-vector differences**. Not just40 scalar layer weights, and lr0.1 is **not a LoRA LR**. Memory remains substantial per active layer.
- [NLG README](https://github.com/JingXuTHU/Scalable_Model_Merging_with_Progressive_Layerwise_Distillation/tree/main/NLG): WizardLM/WizardMath/Code-Alpaca13B teachers;16 calibration examples/domain, batch16, **100 epochs/layer**, lr0.1,40 layers; for a two-domain merge ≈200 updates/layer/8,000 total (computed); inputs capped512, actual tokens NR. Calibration from AlpacaEval/GSM8K/MBPP is excluded from final eval. Requires explicit Transformers `LlamaModel.forward` patch—old Llama2 code, not Qwen plug-and-play.
- [Paper Table3](https://arxiv.org/pdf/2502.12706): math+code merge normalized average **.8288 vs .6711 task arithmetic, .7868 TIES**; GSM8K62.79 vs64.67 arithmetic, HumanEval12.80 vs8.54. Thus preserves a **better joint frontier**, not every individual score. Character-source teacher would need its own domain and held-out character evaluation; no such experiment reported.

## Gaps / residual risks
No controlled MoE graft-preservation result; no independent reproduction performed. Mutable branches/old dependencies need pinning; most papers omit realized supervised tokens. Teacher matching can erase the character; graft-teacher matching can preserve its verbosity/moralizing. Compression's persistent structural edit is fundamentally easier than preserving a behavioral delta. Our maths statistic pools only11 code-checked GSM8K/JSON items with repeated samples—not a full GSM8K test—and small character-score gaps have order noise. Skill file was unavailable at the expected home paths; no new experimental configuration or training was applied.

## Closest 3 implementations: what to copy next
1. **Minitron / ModelOpt:** copy the **real response-masked forward-KL implementation and frozen teacher plumbing**, not “WikiText healing” by name. In our setting, use SFT-only teacher on capability domains and pre-heal graft teacher on character domains; that two-teacher extension is ours, not NVIDIA's result. Keep the existing two-teacher NLL run as a matched control so the new variable is soft targets, not five simultaneous recipe changes.
2. **ProDistill:** copy **domain→teacher assignment, layerwise feature targets and learned task-vector coefficients**; it is the strongest inspected evidence for keeping source skills simultaneously through a merge. Treat SFT-only and SFT+graft as two experts around the SFT checkpoint, fitting on disjoint capability/character inputs. Start with a small calibration feasibility test; literal elementwise13B coefficient fitting, hardcoded40 layers and lr.1 must not be transplanted to MoE LoRA training.
3. **sail-sg/SDFT:** copy **gold-answer-conditioned rewrites, correctness verification and fallback**, using the *edited* checkpoint to rewrite correct maths solutions while keeping its distribution; then strip privileged answers from training prompts. This is meaningfully different from our failed SFT-only-target repair. Retain separate character replay/eval; the edited model may still moralize. ASFT's `sft+kl` provides optional anchoring to the merged checkpoint, but combining these is an untested extension.
For all three, require an actual character/maths/format/length frontier beating unhealed k=.5—not just lower training loss, restored coherence, frozen graft weights, or recovery toward SFT-only.
