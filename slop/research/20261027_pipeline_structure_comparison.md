# How the other projects actually arrange data pipelines

2026-10-27. Structural audit for wassname: “are they dag, yaml, do they use makefile? what's committed? how do they arrange it?” This is **not** a review of their training text or an endorsement of their recipes.

## Bottom line

**Mostly Python functions/scripts plus YAML or CLI arguments, not a repository-wide workflow framework.** YAML often configures a pipeline; it does not itself declare dependencies. The two Makefiles found in the obvious large post-training projects are principally formatting/checking/release tools, **not data build graphs**. SmolTalk really does use a workflow library (distilabel); SPP uses datatrove inside its distributed generation stage, but its seven-stage outer workflow is a runbook. LASR declares an ordered stage list in YAML. Constitutional Adapters declares stage graphs in Python. Several paper releases are merely separately runnable scripts with README ordering.

For us: keep `just` as the command menu, keep the existing Python chat/document chains, put historical one-offs in **`scripts/data/scratch/`**, and add a short entry-point/stage map. Do not introduce DVC/Snakemake/Prefect/Hydra to rename a directory. Preserve release replay and all cached data. Our new pipeline already has better request/review identity checks than several of these releases; its discoverability, legacy coupling and complete source-to-export coverage are the problems.

## 3. Patterns worth copying, ranked

1. **One obvious route to the maintained pipeline, with scratch outside it.** Copy LASR's root tree + `scratch/README.md`, and science-of-midtraining's library / tested examples / study archive distinction. Our action is a `scripts/data/README.md` linked from root README/`docs/data_provenance.md`, `scripts/data/scratch/README.md`, and the inventory below. No root README claim that “all scripts are current.” Historical code remains in git, not deleted. A non-reference is a clue, not a deletion criterion.
2. **Executable stage order in ordinary Python; YAML for scientific choices.** Copy MSM's readable `DataGenerator.run()` and LASR's explicit stage list where multiple recipes really vary in order. **Keep our fixed chat and A–E functions** rather than converting them into a generic operator framework. SmolTalk's branching distilabel graph pays for its own parallel model tasks; it does not establish a need for that dependency here. `just` names entrypoints and can order commands, but does not infer file dependencies.
3. **Separate released-data replay from fresh sampling.** SPP's `docs/07-reproduce.md` and Constitutional Adapters' reassembly/generation distinction are strongest. Keep our `configs/data/releases/` expected hashes and offline replay. Add path/commit compatibility tests before moving scripts; preserve exact older JSON encoding, absent-input declarations and response caches. “New recipe uses same teacher” is not a release replay.
4. **Small tracked decisions and retrieval/verification manifests, bulk data elsewhere.** Copy SPP's decisions/checksum tiers and Constitutional Adapters' reviewed principle JSON + source/tokenizer snapshots; science-of-midtraining adds explicit result/receipt exceptions and GCS pointers. **Do not copy its storage provider or publish our books.** Our small decision files must become discoverable checked-in inputs or private hash-bound pointers in an approved backup; ignored raw data needs a retrieval record. This report does not choose/authorize a storage service.
5. **Cache identity must include what changed; submission receipts precede paid work.** Constitutional Adapters' `REQUEST_SET.json`/journal/stamp and open-instruct's tokenizer/template/dataset hash show useful boundaries. Our `model_requests.py`/judgement hashes already implement much of this. Keep them; don't regress to OCT/persona whole-file existence checks or LASR position-only snapshot reuse. A resume point must not imply approval of changed text.
6. **Purposeful filenames and artifact names, not ever-increasing experiment numbers.** SPP's `preprocessing/<operation>/`, SmolLM's corpus/method dirs, and LASR's operator names explain purpose. Use stage-family numbers for maintained CLIs; use dated/experiment names for scratch. Numbers describe *artifact invocations*, not a universal total order across source alternatives.
7. **Keep the complete recipe beside a published artifact.** llm_swarm uploads generator source + constitution, science-of-midtraining writes resolved config + dataset manifest, LASR writes stage snapshots + manifest. We already keep resolved recipe/source copies and lineage under `builds/<hash>/`; expose these in the README instead of inventing a new registry.
